feat(quality): ① 向量等价性工具 + ONNX 查询编码器 + index.bin 读取模块

- index_bin.py：index.bin 的读取与强校验（MAGIC / 长度自洽 / footer.complete /
  向量块 sha1），任何不符抛 IndexCorrupt，不返回半可信数据。两个消费者共用，
  避免「两边各写一份读取逻辑」（扩展名集合、MAGIC 长度都因此出过错）。
- encode_queries.mjs：只用 ONNX 编码查询（文本 / 图像）→ 向量 JSON。
  只编码不搜索 —— 搜索留在 Python 侧，使两侧的检索逻辑同处对齐。
- quality_vector_equiv.py：G-B 主判据 ① + A 编码完整性。按库内相对路径 join
  新旧索引，逐条余弦，输出 min/median/<0.99 清单（清单带 ext/size/vectorSource 便于归因）。
- smoke_encode.py：编码器小样验证 + 与索引的同源交叉核对。

本轮发现并修掉两个真实问题：

1. 跨格式字段名漂移：新索引 items.json 用 camelCase relPath（SPEC-identity §5 定义），
   旧 Python 档用 snake_case rel_path。只查后者的结果是 join 全为 None、可配对 0 条。
   现改为显式桥接，并新增「两侧相对路径集合是否一致」检查。
   这不是谁写错了，是格式换代；但跨格式比对必须显式处理。
2. 条目数检查写死 3594，小样运行必然误报 FAIL，改为 --expect-count。

关于重复实现的防线：encode_queries.mjs 与 build_index_onnx.mjs 各有一份 pickEmbedding。

实测余弦 1.00000012，证明两份实现当前等效。
