> 这是一份给你看的发布说明：现在**能用的功能**、**能用但有边界的**、以及**明确还没有的**。
> 口径：只写**已被门禁或真窗口验证过**的东西；没验的一律写「未验证」（AGENTS §4 P6）。

## 0. 一句话：它现在是什么
**一个本地离线素材库管理与检索工具**（Electron 44 + React 19 + Node 24）。

· **素材** = 一张预览图 + 同名压缩包（**允许缺包**）；
· **检索** = 768 维向量（图 ↔ 文同空间）；**只有 compat 相同的库才能合并检索**；
· **数据** = 每个库自己的 `.gs.db`（元数据，可重建）+ `.gs-index.bin`（向量索引）+ 事务日志；全局 `app.db` 记「有哪些库、收件目录」；
· **模型** = 用户自备（不进仓库、不进安装器）。

## 1. ✅ 现在能用的功能（有自动化证据）

### 1.1 库与目录
| 功能 | 说明 |
|---|---|
| **多库登记 / 启用停用 / 切换** | 库列表 + 当前库；「范围（看哪些库）」与「写落点」分离 |
| ⭐ **库根不存在时可见** | 不再静默消失；**三种真原因分开**（不存在 / 不是目录 / 无权限）· **不阻塞启动**（有界 400ms 探测，一个卡死的网络盘不影响其它库） |
| **收件目录登记** | `collect_dir` 表 + 收集；绝对路径必须**存在且是目录** |

### 1.2 浏览与取图
| 功能 | 说明 |
|---|---|
| **素材墙** | 分页 + **12 种排序**（relPath/folder/stem/imageMtime/imageSize/archiveSize × 升降）· SQLite 默认 NULL 序（**后端权威，界面不重排**） |
| **筛选 facets** | 按扩展名 / 有无压缩包 / 文件夹 |
| **缩略图** | 自定义 `thumb://` 协议 + 磁盘缓存（原子写 + JPEG 首尾校验）；失败映射 **403（安全拒绝）/ 415（解码失败）/ 500（内部）** |
| **条目详情** | 大图 + 元数据 + 预览图/压缩包两条路径 + 索引状态 + 四分区 + 禁用原因 + 「检查变更」 |

### 1.3 搜索
| 功能 | 说明 |
|---|---|
| **以图搜图** | 库里选图 / 库外按钮选文件（拖入与粘贴见 §3） |
| **文本搜图** | 768 维，L2 归一，余弦排序 |
| **band 分档** | 分数档由引擎给，**界面不自算阈值、不跨模态比分数** |
| **跨库** | 仅合并 compat 相同的库，并**说明为什么排除**别的库 |

### 1.4 体检（诊断页）
| 功能 | 说明 |
|---|---|
| **检查项 + 徽标** | 徽标写「**检查项全部通过**」（「说得比它测的多」这句已消灭） |
| **重建元数据** | **两段式确认**（取消 ⇒ 一个 IPC 都不发）+ 忙碌指示 + 重建报告 + **自动复检** |
| ⭐ **孤包独立异常类别** | 「只有包、没有图」：**不算素材 · 不是损坏 · 重建修不好**；计数 + 明细（上限 50 + 截断标记）；**不翻 ok** |
| **不可用库横幅** | 同「库根不存在」那条 |

### 1.5 应用健康（本轮新增）
| 功能 | 说明 |
|---|---|
| ⭐ **`appHealth`（第 22 个方法）** | 顶栏**总是**显示一个低调入口（健康时也写「无事发生」，不是空白）；诊断面板给**三样事实**：次数 / 首条原因 / 首条时间 |
| **隐私口径** | **只读 · 恒成功 · 不含路径/用户名/堆栈正文 · 不上报 · 不弹窗 · 不阻塞**；摘要清洗有**能红**证明 |
| **为什么不显示「上次崩溃」** | 那需要持久化 ⇒ 会留下**下次启动必然过期的假标记** ⇒ 宁可不显示，也不猜（日志是它的去处） |

### 1.6 安全（有专门断言）
| 项 | 状态 |
|---|---|
| **渲染进程** | `sandbox: true` · 严格 CSP · **无远程内容** · preload 只暴露 `invoke`/`onEvent`/`platform` 三键 |
| ⭐ **绝对路径来源闸门** | `libraryAdd.root` **必须来自本次系统对话框返回过的路径**（`C:\Windows` 这种真实存在且是目录的也拒）；`collectDirAdd` 无选择器 ⇒ 只校验「存在且是目录」并**如实标注缺口** |
| **契约声明** | 「渲染层传不进绝对路径」这句**已改成如实**（列出三处例外与两道防线） |
| **库内写入不变式** | 除保留命名空间（`.gs-*` ∪ `.gs.db` 家族 ∪ staging）外，**素材目录一律只读** |

### 1.7 任务台账（本轮新增，**尚未接到界面**）
| 功能 | 状态 |
|---|---|
| ⭐ **job 表（第 7 张表）** | 进度**持久化**：`progress_done`（**只增不减**，模块层 + **数据库 trigger** 两层守卫）· `progress_total`（**可空，不编数字**）· `phase`（会变 ⇒ 不静默）· `cursor_json`（断点续跑）· `heartbeat_at_ms` |
| ⭐ **崩溃恢复** | **打开库时**自动结算：`running` 但心跳过期 ⇒ 判 `failed`（**否则界面会永远显示一个不存在的进度**）；只读连接**绝不写**；坏游标**不阻断开库** |
| **边界** | 现在的能力是「**库里能记、能续、能判崩溃**」，**不是**「界面上能看到」—— 接线见 §3 |

## 2. 🔧 怎么跑（开发）
`~powershell
npm install
npm run dev        # 开发（含 HMR）
npm run build      # 三端产物 → out/（不需要手动设 TEMP，构建已自给自足）
npm run e2e        # 真窗口 E2E
`~

**一条命令验质量**（每次收工都跑这个）：
`~powershell
npx prettier --check . ; npm run lint ; npm test ; npm run typecheck ; npm run build ; npm run e2e
`~

**模型放哪**（用户自备）：按 SPEC §2 顺序 —— **你指定的路径 → 程序目录 → userData**；启动时检测不到会给明确指引。

## 3. ⚠️ 能用但有边界 / 还没接上的

| 项 | 现状 |
|---|---|
| ⭐ **在应用里建索引** | **还不能**。索引构建器现在是**命令行脚本**，正在重构成可被主进程调用的函数（IDX-1）；**再往前必须恢复三个契约方法**（`indexStart`/`indexCancel`/`indexResume`）—— 那是**契约变更，等你批准**。现有 `data/idx-full-v2` 是命令行构建的 |
| **进度/阶段/断点的界面显示** | 未接。台账已在库里，界面看不到（P6：不声称可用） |
| **入库 / 增量** | 侧栏是禁用占位（等索引接线） |
| **文档检索（F7）** | **门控未开工**：需先拿到 **10–30 份真实文档**并确认格式分布；侧栏已补**禁用占位 + 进入条件**（不再是「连入口都没有」） |
| **设置中心** | 未做（P4-4） |
| **快捷键 / 命令面板** | 未做（P4-6；`cmdk` 已装但零 import） |
| **以图搜图：拖入 / 粘贴** | 只有按钮路径 |
| **回收站 / 删除条目** | **未实现**，而且它与 SPEC §2.1「素材目录一律只读」**正面冲突** ⇒ 需你先拍板口径（`.gs-trash/` 进保留命名空间 + §2.1 措辞 + 两个错误码） |
| **库重新定位** | 未做（当前是「显示不可用 + 原因」，不自动清理、不自动重建） |
| **模型一键下载** | 未做 |
| **安装器 / 干净机器安装** | **未验证**。已做的是 `--dir` 打包冒烟 + asar 内容审计（306.0 MB 未打包部分 = `onnxruntime-node` 287.1 + `sharp` 18.9；`onnxruntime-web` 138.7 MB **没被加载**）；**NSIS 安装包 + 干净机器冷启动/取图/编码仍待做**（T-38） |
