# PRD · 默认形态改为「素材管理 + 简单 ID 搜索 + 文本搜索」，以图搜图降为可选项

| 日期 | 2026-10-19 |
| 调查对象 | **Eagle**（eagle.cool；以下简称 Eagle） |

| 一句话 | 把产品从「必须装模型的语义搜索工具」改成「**开箱即用的本地素材管理器**；ID/文件名/文本检索是默认能力，**语义检索与以图搜图是可选增强**」 |

> **所有者口径确认（2026-10-19，已按此更新本 PRD）**
> 1. 「文本搜索」= **L0 关键词匹配**（文件名/路径/备注等），不是语义检索。
> 2. 「简单的 ID 搜索」= **uid（12 位 hex，4–11 位前缀）+ 文件名**。
> 3. **标签/收藏不进 P0**（放 P1；数据层第二批表随 P1 加迁移）。
> 4. 语义/以图搜图**默认关**；用户需要而系统还没模型/索引时，**跳转到设置页的引导页与管理页**（而不是只给一句禁用原因）。
> 5. 仍待定：新增检索方法的形态（新 `localSearch` vs 扩展 `search` 的 `mode:'local'`）——见 §11。

## 1. Eagle 产品调查

### 1.1 产品事实（来源见括注）

- 定位：面向设计师的**本地素材管理器**（collect → organize → search → browse 四段闭环），Windows 10+ / macOS 10.15+（Eagle 4.0.0 Build23，2026-04-01）。
- 核心组织能力：**文件夹 · 标签 · 智能文件夹 · 评分 · 注释 · 自动标签 · 查重**；检索能力：**关键词 · 颜色 · 多维筛选 · 随机 · 快速切换**；浏览：悬停预览 · 空格预览 · 多窗口 · 手势缩放；采集：浏览器插件（批量保存 / 高清下载 / Alt+右键 / 截图）· 拖拽 · 剪贴板 · 网页与视频书签；插件体系（JS/HTML）与 Web API。
  - 来源：[eagle.cool 首页](https://eagle.cool/)（访问 2026-10-19）
- 商业模式：**一次性买断 US$34.95**，含后续所有版本更新、2 台设备、无限次解绑；Win/mac 同授权、含浏览器扩展。宣称 40 万+ 用户。
  - 来源：[eagle.cool/store](https://eagle.cool/store)（访问 2026-10-19）
- **AI 的接法（最关键的一条）**：AI 不是核心，而是**后来以插件形式追加的可选层**：
  - `AI Search`（2026-03 发布）：**反向图搜**（参考图找视觉相似）+ **自然语言搜索**；全部本地、离线、装插件后免费；GPU 模式在 NVIDIA / Apple Silicon 上比 CPU 快 30–50×，AMD/Intel 只能 CPU（来源：[AI Search 发布文](https://eagle.cool/blog/post/eagle-plugin-ai-search)，访问 2026-10-19）。
  - 注意其自然语言搜索的边界：**只对资产已有的文本元数据（文件名/描述/备注）做语义匹配**，不是"看图生文"；官方自己写明"没有文字信息的图，语义搜索没有东西可匹配"。
  - `AI Action`（2026-03）：批量自动命名/打标签/归档/写备注；`Eagle MCP/Skill`：外部 AI 助手操作图库；`Eagle 5.0` 预告把 AI 作为工作流内核（AI Search / AI Action / MCP），承诺买断用户免费升级、本地优先、模型自选（GPT-5 / Ollama）（来源：[5.0 预告](https://eagle.cool/blog/post/eagle5-teaser) · [5.0 开发进展](https://eagle.cool/blog/post/eagle-v5-development-update)，访问 2026-10-19）。
  - 一个成熟的取舍：**新 AI 能力不绑大版本升级**——官方明确说不想让用户为了试用 AI 去承担 5.0 的兼容/迁移风险，于是把 AI Search/Action 先做在稳定的 4.0 上（来源：AI Search 发布文）。

### 1.2 Eagle 做对了什么（对我们的启示）

| # | 观察（事实） | 对我们的启示 |
|---|---|---|
| E1 | 基础四段闭环（收集/整理/检索/浏览）**不依赖 AI**，闭眼可用 | 默认形态必须**没有模型也能完成主流程**；模型是加分项，不是门槛 |
| E2 | AI 能力**插件化**、可装可卸、有独立发布节奏 | 我们的「语义检索/以图搜图」也应是**可开关的可选模块**，而不是产品唯一入口 |
| E3 | 检索的第一层是**元数据**（文件名/标签/文件夹/评分/备注/颜色），速度快、可解释 | 默认检索必须先做**结构化/关键词检索**；语义与视觉是第二层 |
| E4 | 语义搜索只吃**已有文本元数据**；没有文字信息就没有效果 | 把力气花在**让素材有元数据**（命名/备注/标签）上，比堆模型更能提升"找得到" |
| E5 | 本地优先、零上传、买断制是明确卖点 | 我们的本地/离线/隐私立场与之一致，继续作为差异化 |
| E6 | 4.0 → 5.0 升级有兼容风险，所以新能力先落在稳定版 | 我们的默认形态也应**先在现有 4 层架构上落地**，别为了 AI 大改地基 |

### 1.3 Eagle 的局限（我们的机会）

- 【判断】Eagle 的检索默认仍是"文件名/标签/文件夹"的**字面匹配**；自然语言搜索只覆盖文本元数据，对"没命名、没备注"的图无能为力 —— 这与我们已有的**本地语义向量**形成互补：我们的语义/视觉检索是"可选但更强"，Eagle 的元数据检索是"默认且更快"。
- 【判断】Eagle 是**买断 + 插件生态**的产品，不做"库根可移植/多库合并/口径可审计"这类工程化能力；我们的「两个数据库 + 库根只读 + 可重建索引」在**数据可迁移、可审计**上是差异化。
- 【判断】Eagle 大量能力面向设计师个人；我们的真实库是 3594 条「预览图 + 同名压缩包」的素材库（`data/libraries/L1`），更像**素材/资源库管理 + 取用**，而不是灵感收藏 —— 默认形态应围绕"盘点、找、取"而不是"收藏、打标签"。

> 同类产品（Billfish / Pixcall 等）本轮**未逐一实测**（P6：不声称未验证的对比结论）；如需横向对比，另开调查卡。

## 2. 为什么现在要改（问题陈述）

1. **产品主入口依赖模型**：当前检索（`search` 的 `text`/`image` 模式）都要求模型与索引就绪；模型缺失时用户能做的事非常有限（只能逛库）。冷启动/交付/换机都会把"主流程"卡住 —— 这是**可用性风险**，不是体验细节。
2. **以图搜图目前是"半成品"**：查询图只能整图（文件/拖拽/粘贴文件），框选查询没有（FR-004 ❌），截图位图粘贴被契约门控（U36 暂不批准）⇒ 作为**默认入口**不成立，作为**可选增强**才诚实。
3. **"简单的 ID 搜索"完全没有**：`search` 空文本直接 `BAD_REQUEST`；没有按 uid/文件名/目录的即时检索；用户在 3594 条里找一个已知 ID 只能翻浏览页（FR-018 有浏览，但没有"输入即定位"）。
4. **素材管理太薄**：批量操作、标签/收藏、回收站都还没有（FR-019 ⚠️、TRASH-1 待排期）；Eagle 的默认形态正是这些"日常整理动作"。
5. **Eagle 5.0 把 AI 做成免费升级的插件层**（来源：5.0 预告）⇒ 我们若把 AI 当唯一卖点，会和"免费升级 + 40 万用户"正面撞车；改为"**默认好用 + 可选智能**"更稳。

## 3. 产品定位与目标用户

### 3.1 新定位（一句话）

> **本地素材库管理器**：打开就能浏览、筛选、按 ID/文件名/文本找到素材，并一键取用；
> **智能检索（语义 + 以图搜图）是可选增强**，由用户自己决定是否引入模型。

### 3.2 目标用户与场景

| 用户 | 场景 | 默认形态要满足的 |
|---|---|---|
| 素材库主人（本机 3594 条素材） | 知道 ID/文件名，要快速定位并取包 | ID/文件名即时检索、结果直接可复制/定位/取件 |
| 设计/内容使用者 | 记得"大概是什么"，但没命名 | 关键词（目录/扩展名/备注）+ 可选的语义检索 |
| 偶尔使用者 | 换电脑/模型没装，只想找图 | **无模型可用**：浏览 + ID/文件名/文本检索全可用 |
| 进阶用户 | 想要"以图搜图/近重复" | 打开可选模块后才出现入口；未就绪时**如实**说明原因 |

### 3.3 成功标准（本 PRD 建议，非实测）

- 无模型、无索引时：**启动 3 秒内**可浏览、可 ID/文件名检索；主流程（找 → 用）不出现"请先安装模型"的阻断。
- 本地检索：10k 条量级下 P95 ≤ 100 ms（输入 150 ms 防抖后）。
- 智能检索：**默认关闭**；打开后行为沿用现有 `search`（text/image）。未启用/缺模型/缺索引时点入口 → **跳转设置页**（引导装模型 + 管理建索引 + 开关），就绪后回到原查询。
- 证据要求：每项验收都进 `reports/`（门禁照旧：prettier/lint/tsc/单测/build/e2e/s4）。

## 4. 默认形态：信息架构与交互

### 4.1 首页 = 库浏览（默认落地页）

```
┌ 顶栏：统一搜索框（默认「本地检索」 ▾ 可选「智能检索」）   ⌘K / Ctrl+K 聚焦
├ 左侧栏：库 ▾ · 目录树（folder） · 标签（P1） · 收藏（P1） · 最近使用
├ 主区：工具栏（筛选：目录/扩展名/有无包/尺寸/时间 · 排序：名称/大小/时间/相关度 · 视图：网格/列表）
│       多选工具条（P0）：复制路径 · 导出/取件 · 定位 · 加入标签（P1）· 排除索引
│       网格（虚拟滚动/分页）：缩略图 + 文件名 + 大小 + 类型 + 收藏/标签角标
└ 详情页：预览 · 元数据（ID/路径/尺寸/大小/时间/包）· 备注/评分（P1）· 操作（复制路径/定位/取件）
```

- **默认落地页从"搜索页"改成"浏览页"**（或搜索页在无查询时直接呈现浏览网格）。现状：搜索页空态是引导文案，浏览页在二级入口 ⇒ 默认形态应把"库"放在第一屏。
- 顶栏搜索框是**唯一检索入口**，默认模式「本地检索」；「智能检索」是同一框内的可选模式（不是另一个产品）。
- 无查询时展示"全部素材"（分页/虚拟滚动），而不是空白。

### 4.2 统一搜索框：三档能力（默认只开第一档）

| 档 | 名称 | 依赖 | 默认 | 匹配对象 | 说明 |
|---|---|---|---|---|---|
| **L0** | **本地检索**（默认） | 无模型、无索引 | ✅ 开 | uid / 文件名（stem/display_name）/ 扩展名 / 目录 / 备注（P1） | SQL 级匹配，即时、可解释、离线 |
| **L1** | 语义文本检索 | 模型 + 索引 | ⛔ 默认关（可选开） | 文本向量（现有 `mode='text'`） | 找不到词但"意思相近"时用；未就绪 ⇒ 点入口**跳设置页**（2026-10-19 口径） |
| **L2** | 以图搜图 | 模型 + 索引 | ⛔ 默认关（可选开） | 图像向量（现有 `mode='image'`）+ 近重复角标（已实现，k=10） | 整图查询；框选/截图另卡（FR-004 / U36） |

**L0 的输入判定（无需用户选模式）**：

1. 去掉首尾空白后，若匹配 `^#?[0-9a-f]{4,12}$` ⇒ **ID 检索**：
   - 12 位 = uid 精确；4–11 位 = uid 前缀（SQL `LIKE 'prefix%'`，结果标注"前缀匹配"）；
   - 大小写不敏感（统一 lower）。
2. 若以 `ext:` 开头 ⇒ 扩展名精确匹配（`ext:psd`）。
3. 若以 `#tag` 开头（P1）⇒ 标签检索。
4. 其余 ⇒ **文本检索**：`display_name`/`stem`/`rel_path`/备注 的子串匹配（大小写不敏感），按"名称命中 > 路径命中 > 备注命中"排序，并高亮命中片段。
5. 结果为空：区分"库里没有"与"输入格式像 ID 但不存在"两种文案；**不自动回退到语义检索**（避免"输错 ID 却看到不相关图"）。

**模式可见性规则（防误导 · 2026-10-19 所有者口径）**：

- 模型/索引未就绪 ⇒ L1/L2 入口**保持可见、可点**；点击**跳转到设置页的引导页（安装模型）+ 管理页（模型状态 / 建索引：开始·取消·续跑）**，而不是只给一句"禁用原因"。用户在设置里完成后回到原查询。
- 设置页需承载两条链路：**模型**（缺模型 → 安装指引/路径检查）与**索引**（缺索引 → 建索引入口，复用 IDX-2b/IDX-3 已有的任务能力）。
- 未启用开关时：入口可见（灰态/提示"可选功能"），点击同样走设置页开关；**不隐藏成"产品没这个能力"**（P6：不假装可用，也不谎称不存在）。

### 4.3 结果区

- 复用现有 `Gallery`/`PhotoCard`：缩略图 · 名称 · 分数/命中类型 · 路径操作 · 近重复角标（仅 L2）。
- L0 结果不显示"分数/band"（避免把字面命中伪装成语义分），显示**命中类型**（ID / 文件名 / 路径 / 备注）。
- 空结果与弱匹配：沿用 NOMATCH-1（U38）的 shortfall 规则（`band='low'` 时"仅供参考"）；L0 无 band ⇒ 只显示"没有匹配"。

## 6. 可选模块：智能检索（语义 + 以图搜图）

### 6.1 开关与状态机（2026-10-19 所有者口径：默认关 + 缺依赖跳设置）

```
[未启用/未就绪] --点 L1/L2 入口--> 跳转设置页（引导：装模型 / 管理：建索引 / 开关）
                                          ├--就绪并开启--> [可用]（回到原查询/继续操作）
                                          └--仍未就绪--> [设置页说明缺什么，留在设置]
[可用] --用户关闭开关--> [未启用]（立即隐藏"智能检索"模式，不删模型/索引）
```

- 用 L1/L2 **不再要求"先开开关再点"**：点入口即进入设置页，由设置页把"开关 + 模型 + 索引"三件事一起呈现（引导页 + 管理页）。
- 存储：`app_setting`（应用级）键如 `features.semanticSearch` / `features.visionSearch`，默认 `false`。
- 首次进入设置页的引导时给**一句话说明**（本地运行、不上传、模型来源/大小），用户确认后再检测模型。
- 状态查询：新增只读能力（或扩展现有 `appHealth`/`libraryHealth` 的返回，不新增第二个健康接口）——二选一在 §11 定。

### 6.2 以图搜图（L2）的具体形态（可选、非默认）

- 入口：搜索框右侧"以图搜图"按钮（**始终可见、可点**）；支持**文件选择 / 拖拽 / 粘贴图片文件**（UX-1c 已有）。未启用/缺模型/缺索引时，点击**跳转设置页**（引导装模型 + 管理建索引 + 开关），就绪并开启后回到搜索界面。
- **不做**：截图位图直接粘贴（U36 未批新增 IPC，保持如实拒绝并提示先存文件）；框选查询（FR-004，另卡）。
- 结果：沿用现有 `mode='image'` + `nearDuplicate`/`phashDistance`（U39 已交付，k=10）；查询图来源：库内条目（`imageRef`）或外部文件（`queryImagePath`）。
- 隐私提示：本地编码、不上传（与 Eagle AI Search 的卖点一致；Eagle 来源同上）。

### 6.3 语义检索（L1）

- 入口：搜索框模式下拉里的"智能检索（语义）"（**始终可见**）；未启用/未就绪时点它 → 跳设置页（引导/管理/开关），而不是灰着不给路。启用并可用后行为 = 现有 `mode='text'`。
- 行为：现有 `mode='text'`；结果 band/近重复等沿用；`MODEL_MISSING`/`INDEX_MISSING` 文案与设置页联动（点错误提示可直接跳到设置/建索引）。
