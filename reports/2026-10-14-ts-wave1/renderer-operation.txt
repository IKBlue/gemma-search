4.1 Node 24 ESM **不**把 `./x.js` 映射到 `x.ts`；Vite 7 **会**

Node 探针（scratch：同目录只有 x.ts，无 x.js）：

    at finalizeResolution (node:internal/modules/esm/resolve:275:11)
    code: 'ERR_MODULE_NOT_FOUND'
$ node imp2.mjs     # import { v } from "./x.ts"

$ node -v
v24.14.0

Vite 7 源码（node_modules/vite/dist/node/chunks/config.js:32898-32913）：
    const knownTsOutputRE = /\.(?:js|mjs|cjs|jsx)$/;
    const isPossibleTsOutput = (url) => knownTsOutputRE.test(url);
    function tryCleanFsResolve(file, options, tryIndex = true, skipPackageJson = false) {
        ...

⇒ Vite 的判据是 **specifier 长什么样**，与 importer 是不是 TS **无关**。
  所以范围外 pages/*.jsx 里的 `from '../store/tasks.js'` 在 Vite 下能解析到 store/tasks.ts
  （构建实测：client environment ✓ 254 modules transformed）。
⇒ 但 `node:test` 直接加载时不行。⇒ **范围内相对 import 必须写显式 `.ts`**，
  这与 tsconfig.node.json 的注释「Node ESM 必须写显式扩展名 ⇒ .ts 之间只能 import './x.ts'」、
  以及仓内既有 `apps/desktop/tests/permissions.test.mjs:23 → '../src/shared/ipc.ts'` 完全一致。

5. 环境问题（是环境，不是产品）—— 必读
================================================================
`npm run build` 在**默认 TEMP** 下会失败：
    error during build:
    [vite:esbuild-transpile] remove C:\Users\ADMINI~1\AppData\Local\Temp\esbuild-<hash>: Access is denied.

把 TEMP/TMP 指到仓库内可写目录后 **EXIT=0**，三端产物齐备（§3.2）。
判据：
  · 失败点在 **254 modules 全部 transform 成功之后**的临时文件清理步骤，不是模块解析、不是类型；
  · 同一现象在改动**前**也会出现（本轮最初那次 `npm run build`，未改任何文件时，同样是这一条）；
  · 与 §4 的探针同一根因：该沙箱下 esbuild 在系统临时目录**删除**自己的临时文件被拒。
⇒ 属沙箱/环境限制，**不要**固化 `$env:TEMP` 进产品配置；复跑构建时临时指定即可。
