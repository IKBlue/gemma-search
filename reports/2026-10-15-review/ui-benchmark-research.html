UI/UX Benchmark Research

同类项目界面做法调研

基于网络搜索与 GitHub 源码阅读，梳理「本地素材库 / 语义图像检索」这一品类的主流界面做法，并映射到 gemma-search 的重设计方案。

01对标项目清单

E
Eagle · 素材管理标杆
同品类最成熟的商业产品。刚发布的 AI Search 插件与本项目几乎同构：以图找图 + 自然语言搜索 + 全程离线。界面 = 侧栏（文件夹/智能文件夹/标签）+ 工具栏 + 检查器（右侧详情）+ 图片列表 + 筛选器 + 主题皮肤。
I
Immich · 自托管相册
开源照片管理 + CLIP 语义搜索。Smart Search（自然语言）+ Advanced Search Filters（AND/OR 组合筛选）。v3.2 重写了搜索 UI 与搜索 API。
L
Local-Image-Finder · Electron
Electron 30 + React 18 + Tailwind + shadcn + CLIP，与本项目技术栈几乎一致。特色：Chat 式搜索 + 会话历史、Library 页展示历史会话网格、搜索框内嵌模型质量档选择器。
T
tics · Electron + Python
Electron + electron-vite + shadcn + TanStack Router + Python sidecar，架构最接近本项目。四步首启向导（选库→硬件→模型→索引）、侧栏目录树 + 索引进度 + 硬件信息面板、结果卡相似度徽标。
Z
zvec-image-search · 极简
最简 Electron + CLIP 实现：一个搜索框 + 结果网格 + 余弦分数 + 灯箱预览 + 复制。可作为「最小可用」参考。
V
VBLIS 等
VBLIS / Clip-Image-Search / scene / Find / Nimbus / eidetic / image-indexer：本地 VLM 图像检索，多为核心功能验证型，UI 偏简。

02十条主流界面做法（含代码证据）

① 搜索框即中心 主流

几乎所有同类项目把搜索框放在顶栏或首屏中央作为第一入口。Eagle 的 AI Search 入口在搜索栏右侧；Local-Image-Finder 的 EnhancedSearchInput 直接放进 TopBar；tics 用 chat-input 占据主屏。

② 多模态合一输入框（不是「文字/图片」切换）趋势

主流做法是把「打字 + 粘贴图片 + 拖拽图片 + 选图按钮」合并进同一个输入框，而不是切换模式。tics/chat-input.tsx 支持 paste/drag/file-picker 三合一；Local-Image-Finder/EnhancedSearchInput.tsx 是「文字框 + 图片上传按钮 + 模型选择器 + 提交按钮」一行排开，选中图片后图片按钮高亮、文字框出现清空(X)。

证据：EnhancedSearchInput.tsx —— text input + Image button + Select(Default/Fast/Accurate) + submit，一处含 X 清空。

③ 结果卡 = 缩略图 + 相似度徽标 + 名称底部渐变 主流

tics/image-gallery.tsx 的卡片：右上角 Badge「Similarity: XX%」、底部黑色渐变 scrim 压文件名、hover 淡入操作层、懒加载缩略图。这是「一眼看到分数与名字」的标准形态。

④ 悬浮操作 + 右键菜单 本项目已做

tics 的 GalleryCard hover 显示「查看/复制」按钮，右键 ContextMenu 提供「Copy / Open」。桌面应用标准交互，gemma-search 原型已有 hover「定位/取件」，但缺右键菜单。

⑤ 侧栏 = 导航 + 索引进度 + 目录树 + 硬件状态(底部) 值得借鉴

tics 的 app-sidebar.tsx：顶部 Logo → Home/Settings 导航 → IndexingStatusPanel（索引进度）→ FolderTree（库目录树）→ 底部 HardwareInfoPanel（GPU/CPU 状态）。把「设备、索引进度」常驻侧栏，比藏在设置里更符合「状态可见」原则。

⑥ 分步首启向导（含硬件检测与索引步骤）本项目部分

tics 四步：step-01-library → step-02-hardware → step-03-model → step-04-index。Local-Image-Finder 三阶段自动完成（下载模型→样例→建索引），带进度条。gemma-search 现有向导只有「选库→模型→文档」，缺「设备检测」与「建索引进度」两步。

⑦ 设置页按功能分区 本项目已做

tics 的 settings 分 folder-settings / indexing-settings / model-settings / search-defaults / about 五个区；Local-Image-Finder 的 Settings 有 watched folders、模型质量档、相似度阈值、结果数、主题。gemma-search 原型已分区（模型/取件/外观/快捷键/诊断），方向一致。

⑧ 搜索会话历史 / Chat 式搜索 差异化机会

Local-Image-Finder 用 Chat.tsx 做「对话式搜索」并把每次查询存成会话，Library.tsx 用网格展示历史会话（每次查询 + 结果预览）。这是本地检索应用里较新的差异化方向，值得 gemma-search 考虑「最近查询/历史」。

⑨ 模型质量档选择器放搜索框 实用

Local-Image-Finder 在搜索框里放 Default / Fast / Accurate 三档模型选择。对应 gemma-search 的 seq / 精度档，可把「设备/档位」做成顶栏可见的 chip 而非隐藏配置。

⑩ 懒加载 + 分页 / Load more / 虚拟滚动 本项目已做

tics 用 pageSize=20 的 Load More 分页 + 缩略图懒加载；gemma-search 用 @tanstack/react-virtual 虚拟滚动，是更高级的解法，保留即可。

03对 gemma-search 重设计的落地建议

建议状态说明
合并「文字 + 以图搜图」为一个输入框（粘贴/拖拽/选图三合一）需改当前原型用「文字/以图搜图」切换；主流是合一输入框 + 图片按钮，更省一步。这是与 Eagle AI Search 对齐的关键改动。
结果卡加「相似度 % 徽标 + 文件名底部渐变」需改当前有分数条，但缺右上角 % 徽标和底部渐变压字（tics 做法）。
侧栏底部加「索引进度 + 硬件状态」两个 panel需改当前只有 model-status 一行；参考 tics 的 IndexingStatusPanel + HardwareInfoPanel。
首启向导补「设备检测」与「建索引进度」两步需改参考 tics 四步向导。
右键菜单（复制 / 打开 / 定位 / 取件）新增桌面应用标配，当前缺。
搜索历史 / 最近查询新增Local-Image-Finder 的 Library 会话网格是差异化点。
库列表 + 库详情管理已补上轮已加入「素材库管理 + 库详情」两屏。
命令面板 ⌘K、批量选择、深/浅色、HIG已做已在前版原型落地。
