【A. jobId 加密随机】

--- A1 改前 → 改后 ---
改前（packages/engine/src/engine.ts:613）：
    const jobId = `j-${Math.random().toString(16).slice(2, 6)}`;
  ⇒ 4 位 hex（取值空间 16^4 = **65536**）且是 Math.random（非加密随机）。engine.ts 的 `jobs` 是 Map，
    撞了就把两次取件记成同一个 job；AGENTS 明写「ID 新增处一律用现成实现，不自己拼随机」。
改后：
    + import crypto from 'node:crypto';   （文件头）
    const jobId = `j-${crypto.randomUUID()}`;
为什么不是放宽：
  · 随机源由 Math.random（可预测、65536 空间）换成 **CSPRNG 的 UUIDv4**（122 位随机）；
  · 断言是**新增**的（256 次互不相同 + `j-`+v4 形状），不是把旧断言改松；
  · **保留 `j-` 前缀**是为了与 fake 引擎的 `j-fake-*` 同族（界面/日志/契约口径不变），
    与"保留弱随机"无关 —— 前缀后的随机段才是被替换的东西。

--- A2 能红（退回旧写法 ⇒ 断言必红；已还原复绿）---
手法：把 engine.ts 那行临时改回 `j-${Math.random().toString(16).slice(2, 6)}`，跑新单测。
原始输出：

    AssertionError: N 次取件的 jobId 必须互不相同（旧写法 4 位 hex 只有 65536 种）
  ℹ tests 2 / pass 1 / fail 1        REDA_EXIT=1
  （同一条用例里的**形状**断言是确定性的：任何 4 位 hex 都不匹配 UUID 正则；本次互不相同那条先红，
    说明 256 次里已经撞了 —— 两条都指向同一个缺陷。）
红锚（固定在测试文件里，不需要靠运气）：用**固定种子的 mulberry32** 复现旧写法的取值方式 ⇒
  「旧写法在固定种子下必然撞（实得第 N 次）」+「j-1a2b 不满足 UUID 形状」。
还原后：✔✔ 两条全绿 · GREEN_EXIT=0；`grep RED-PROOF packages/engine/src` = 0 命中。

【B. 指纹 vs 扫描器：「什么算素材」收敛成一份实现】
===============================================================================

--- B1 改前 → 改后 ---
改前：
  · packages/engine/src/fingerprint.ts：只跳 `isReservedLibraryName` ⇒ `.DS_Store` / `.picked.json` 之类
    **隐藏项被算进库指纹**（一个编辑器 churn 就能让 doScan 报「库被改过」，而扫描 diff 什么都不显示）；
  · packages/engine/src/scanner.ts：自己写两分支（保留名 / `startsWith('.')`）⇒ 与指纹**两套口径**（P1）；
  · main/library-rebuild.ts 的 materialDigest：也只跳保留名 ⇒ 与扫描器又不一致。
改后（**唯一判据** = packages/engine/src/gs-names.ts 新增的两个导出）：
    export type EntryClass = 'reserved' | 'hidden' | 'material';
    export function classifyEntryName(name): EntryClass    // 先保留名、再隐藏项、否则 material
    export function isMaterialEntryName(name): boolean     // === classifyEntryName(name) === 'material'
  调用方（同一份实现，三处复用）：
  · scanner.ts：`const cls = classifyEntryName(ent.name)`，reserved/hidden 各自计数后 continue
    （**skippedReserved / skippedHidden 两个计数仍然分开如实**，只是"分类"归一份实现）；
  · fingerprint.ts：`if (!isMaterialEntryName(e.name)) continue;`（保留名 + 隐藏项都不算素材）；
  · main/library-rebuild.ts 的 materialDigest：`if (!isMaterialEntryName(ent.name)) continue;`（卡片允许的唯一改动）；
  · apps/desktop/src/main/gs-names.ts（**纯 re-export 入口**，U11 的既定结构）：把新判据一并镜像过去，
    这样 main 侧仍只从这一个入口取判据（gs-names-single-source 的 S1/S3 继续绿，见 §3）。
为什么不是放宽：
  · 不是把断言改松 —— 是把"素材"的定义**收敛成一份**，并让三方**一致**；
  · 指纹/摘要的口径**变严**：隐藏项以前被计入、现在被排除（`.DS_Store` churn 不再制造假"库被改过"）；
  · `.gs-*` / `.gs.db` 家族 / staging 的排除一行都没松（DF-1 的机械断言原样保留）；
  · 扫描器的两个跳过计数仍然分别如实，隐藏项并没有被"合并进保留项"糊过去。
