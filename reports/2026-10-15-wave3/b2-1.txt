【2. 表 = 设计基线（11 字段行 / 13 物理列 —— J8 用 PRAGMA 逐列钉住）】
`job_id`(PK) · `kind`(CHECK 5 枚举) · `state`(CHECK 5 枚举) · `progress_done`(NOT NULL DEFAULT 0，**只增不减**) ·
`progress_total`(**可空**) · `phase`(可空，**会变**) · `cursor_json`(可空，断点) · `heartbeat_at_ms`(可空，崩溃检测) ·
`summary_json`(可空) · `error`(可空，**人话**) · `queued/started/finished_at_ms`(可空，三个时刻)。
索引：`idx_job_state(state, queued_at_ms)` · `idx_job_heartbeat(heartbeat_at_ms)`（另有 TEXT 主键的内部 autoindex，测试里显式说明"不算声明式索引"）。
⚠️ `job_id`：设计基线写 nanoid，但**本仓库未安装 nanoid**（package.json dependencies 里没有 ⇒ 装它 = 新增依赖）⇒
   用 Node 内置 `crypto.randomUUID()`，**收敛在 `newJobId()` 一处**（job_id 目前不经 IPC ⇒ 不受契约约束）。
   **Lead 2026-10-16 批准**该偏离，理由：零新增依赖 · 与本仓既有做法一致（DF-4 已把 `Math.random` 的 4 位 hex 换成它）·
   `job_id` 是内部 id（不是用户可见文案）⇒ 格式无所谓。
   **偏离写进了两处**（Lead 要求「可发现」，别变成没人知道的差异）：
     ① `main/db/jobs.ts` 的 `newJobId()` 文档注释：基线是 nanoid / 仓库没装 / 三条理由 / 谁批准 / 将来怎么换；
     ② `main/db/migrations.ts` 的 `job` DDL `job_id` 行上的注释（读 DDL 的人也能看到）。
   （AGENTS §1 把 nanoid 列为「已选定」而仓库里没有 = **文档与仓库不符**；AGENTS 只有所有者能改 ⇒ Lead 报所有者，不在本卡处理。）

【3. 四条承诺怎么落地（每条都有断言）】
| 承诺 | 落点 | 断言 |
|---|---|---|
| 进度**单调** | 模块层 `setProgress` 抛 `JOB_PROGRESS_REGRESSION` + **数据库 trigger ABORT** | J3（两层各一条，且"被拒之后进度没被改动"）+ J3b（total < done ⇒ 抛，防超 100% 假进度） |
| 总数**可空** | `progress_total` 可空；初始 `null` | J1（初始必须 null）· J8（NOT NULL 只给 progress_done） |
| `phase` **会变** | `setProgress` 写 phase；不传 = 不改 | J4（两次更新 phase 不同；不传时不被静默清空） |
| **崩溃判定** | `sweepStaleJobs` + `settleUnfinishedJobsOnStartup`（只动 running，心跳新鲜的不动） | J2（判 failed + 人话理由 + **不动进度** + 幂等 + 活着的没被误杀）· J5（重开库后判失败） |

【4. 能红（3 条 · 变异 → 失败原文 → 回滚复绿）】
① 去掉**崩溃清理**（`sweepStaleJobs` 只查不判）：
   `✖ J2 … AssertionError: 只有心跳过期的那个被判失败  actual: []  expected: [ 'j-stale' ]`
   ⇒ 界面会**永远**显示一个不存在的进度（这正是卡片要防的）。
② 去掉**模块层单调守卫**（让数据库 trigger 独自承担）：
   `✖ J3 … AssertionError: 回退必须在模块层被拒  actual: Error: job.progress_done 只增不减…（普通 Error，无 code）`
   ⇒ 证明模块层不是装饰：没有它，调用方拿不到带码的`JobError`，只有 SQLite 的 RAISE 文本。
③ 去掉**数据库 trigger**（DDL 里拿掉 `job_progress_monotonic`）：
   `✖ J3 … AssertionError: Missing expected exception: 数据库级 trigger 也必须挡住（别的写入方绕不过去）`
   ⇒ 证明两层缺一不可。
三条各自回滚后：**23/23 复绿**（job-ledger 11 + db-schema 12）。
