# T-43 证据 · e2e 夹具路径不存在（F-2）⇒ 一批 spec 跑在空库上

> 日期：2026-10-15 · 执行：assert-worker（共享任务板 task-43） · 仓库根 = D:/USERS/Desktop/Agent/gemma-search
> 环境：Windows / PowerShell · Node 24 · Playwright（真 Electron 窗口）

## 0. 结论（三句话）

1. **缺陷成立**：`apps/desktop/e2e/helpers/app.mjs:23` 的 `FIXTURE_LIB` 指向 `apps/desktop/e2e/fixtures/lib-mini`，
   该目录**当时不存在**（仓库根只有 `fixtures/lib-a`）。⇒ `launchWithLibrary()` 把 `GEMMA_LIB_ROOT` 指到空路径，
   而界面照样进主界面、这批 spec **照样全绿**（见 §3 BEFORE：27 passed / EXIT=0）。
2. **已修**：补出 `apps/desktop/e2e/fixtures/lib-mini`（4 张**真图** + 2 个**真 ZIP** + manifest），
   并在 helper 与 gate spec 各加一条**能红**的防线（见 §6）。选 lib-mini 而非 lib-a 的理由见 §1。
3. **修完 0 条测试由绿变红**（见 §5）。原因不是"防线空转"，而是**这批 spec 根本不读库内容** ——
   它们依赖的只是"门禁判定为有库"（`utils/gate.ts:34-35` 只看 `libraries.length`）。**唯一**靠错误路径
   才绿的是 `gate` E1-c：它断的是"侧栏显示库根"，而那条不存在的路径 basename 正好是 `lib-mini`。

## 1. 决策：补 `lib-mini`，**不**改指 `fixtures/lib-a`

理由（都有出处）：

| # | 理由 | 出处 |
|---|---|---|
| 1 | `gate` E1-c 的期望字符串**写死了 `lib-mini`**；改指 lib-a 就必须改这条断言 —— 而它正是本事故的现场证据（它把不存在的路径当"证据"打印并通过），改它会把"哪条绿是空的"抹掉 | `apps/desktop/e2e/gate.spec.mjs:62`（改动前） |
| 2 | `fixtures/lib-a` 的自我定位是**写操作/故障注入**夹具（"合成字节，非真图"），被事务测试复制使用；把只读 UI spec 接到写夹具上 = 两件事耦合 | `fixtures/lib-a/manifest.json:3` · `packages/engine/tests/transactions.test.mjs:4,24` |
| 3 | lib-a 是**合成字节**；本仓库已有实测教训："假字节会让 `thumb://` 解码失败(415)，那会让结果区看起来是坏的" ⇒ 该用**真图** | `apps/desktop/e2e/m0-real.spec.mjs:14-15,37-39` |
| 4 | 名字/意图本来就对得上：helper 常量叫 `lib-mini`，`routing.spec.mjs` 的注释把它叫"迷你夹具库" | `helpers/app.mjs:23` · `routing.spec.mjs:51` |

### 1.1 "这批 spec 需要几条素材才不算空转" —— 如实说：**一条都不需要**

我逐条查了这 27 条（§3/§4 的那批）到底消费什么，结论是它们**不读库内容**：

- 筛选胶囊 `CHIPS` 是**硬编码**的 ⇒ a11y E5-a / styles E4-d,e 断的 VR/CR 胶囊不来自库：`renderer/src/store/search.ts:19-20`。
- 主进程 `indexStatus` 是**零参**方法、读的是已注册索引，与库目录内容无关：`main/index.ts:689-690`。
- `confirm-dialog` 与 `uiux-p0` 的结果来自**打桩的 IPC handler**（`helpers/engine-stub.mjs` 的 `searchOnce()`），不是库：`confirm-dialog.spec.mjs:38,46` · `uiux-p0.spec.mjs:16,25`。
- 其余（routing / a11y / styles / window-security / activity / tasks）只断界面结构、导航、样式与"如实报错"状态。
⇒ 所以"素材条数"**不是**这批断言会不会空转的判据；真正空转的是**路径不存在**这件事。

仍然给 4 张图 + 2 个包（不是 0），理由有二：① "有库"场景应当**真的是个库**；② 防止将来有人加一条读内容的断言时又是空的绿。
防线阈值取 `MIN_FIXTURE_IMAGES = 3`（当前 4 张）。

## 2. 缺陷本体（file:line）

- `apps/desktop/e2e/helpers/app.mjs:23`：`FIXTURE_LIB = new URL("../fixtures/lib-mini", import.meta.url)` ⇒ 解析到 `apps/desktop/e2e/fixtures/lib-mini`。
- 该目录**不存在**（`apps/desktop/e2e/fixtures/**` 为空；仓库根只有 `fixtures/lib-a`）。
- `helpers/app.mjs:87` 把它当 `GEMMA_LIB_ROOT` 传下去；`main/index.ts` 的 `libraryConfig` 按 `library-config.ts:313-319` 无条件接受非空 env。
- 门禁判据只看长度：`renderer/src/utils/gate.ts:34-35` `libraries.length > 0 ? "app" : "wizard"` ⇒ **进主界面**。
- `library-config.ts:394-399` **其实有**存在性检查，但只 push 一条 warning（见 §8）。
