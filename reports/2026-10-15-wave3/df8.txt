【1. 改了什么】
· **atomic-write.ts（扩接缝，DF-4 行为不变）**：
  · `tempPath?`：调用方先断言过合法性的临时路径 —— **必须与目标同目录**，否则抛 `ATOMIC_TEMP_OUTSIDE_DIR`
    （同卷 rename 才原子；跨目录会退化甚至 EXDEV）；
  · `cleanup?`：接管失败清理（调用方要自己的留痕文案）；
  · `AtomicFs.mkdirSync` 改**可选**（不给就**不建目录**）；
  · `AtomicWriteError` 增 `reason`（底层原因）与 `tempPath`（供调用方组文案/清理）。
· **index-file.ts**：
  · 新增 `atomicFsFromIndexFs(fsImpl)`（IndexFs → AtomicFs，**故意不给 mkdirSync**）；
  · 新增 `stageMessageOf(e, target, temp)`（把共享实现的 ATOMIC_* 失败翻回本模块人话）；
  · `writeIndexAtomically` 主体改为一次 `writeFileAtomicSync(target, bytes, { fs, tempPath: temp, validate, cleanup })`；
    临时路径仍**先过 assertWritableGsPath**，再把**同一个**路径传下去（名字规则不再有两份 ⇒ P1 的正解）。
· **index-location.test.mjs**：加 L9 / L10 / L11（§3、§5 引用）。

【2. 三处语义逐条给证据（卡片风险点）】
① **临时名在 .gs- 命名空间、且受 assertWritableGsPath 约束**
   · code：index-file.ts `const temp = assertWritableGsPath(root, path.join(root, INDEX_TEMP_PREFIX + pid + '-' + seq))`
     —— 断言在调用共享实现**之前**；共享实现拿到的是这**同一个**路径（不再自己拼名）。
   · 用例 L9：`w.tempPath === path.join(dir, INDEX_TEMP_PREFIX + process.pid + '-11')`，且
     `calls.write == [temp]`、`calls.rename == [[temp, target]]`、**mkdir 调用 0 次**。
   · 既有用例 L2（命名约束：素材路径/子目录/穿越一律 INDEX_PATH_OUTSIDE_GS）**仍绿**。
② **失败仍抛 IndexFileError 并带自己的码**
   · code：`catch (e) { if (e instanceof AtomicWriteError) throw new IndexFileError('INDEX_WRITE_FAILED', stageMessageOf(e, target, temp) + cleanupNote, { cause: e }); throw e; }`
     —— `AtomicWriteError` **绝不外漏**，码恒为 INDEX_WRITE_FAILED（字节类问题在更前面就用 INDEX_BYTES_REQUIRED 拦掉）。
   · 用例 L10：`err instanceof IndexFileError` + `err.code === 'INDEX_WRITE_FAILED'` + 文案含 `rename 覆盖失败` 与 `已清理临时文件`。
   · 既有用例 L4a（校验不过）/ L4b（rename 失败）/ L4c（连临时文件都删不掉）/ L7（0 字节与非 Uint8Array）/ L8（不建库根）**全绿**。
③ **IndexValidation 报告进 IndexWriteReport 文案**
   · code：`seenValidations.push(validate(tempPath))` 在共享实现的 validate 钩子里 → 调用后
     `const validation = seenValidations.length > 0 ? seenValidations[0] : null` → 进 `validated / count / dim / reason`。
     （用数组接住报告：闭包里赋值对 TS 的控制流分析不友好，数组读法既无断言也不撒谎。）
   · 用例 L3：`validated === true` · `count === 3594` · `dim === 768` · `reason` 匹配 `/已原子写入/`（全绿）。
   · L11：`validateBeforeRename:false` ⇒ 校验器**不被调用** · `validated === false` · `count/dim === null` · reason 含「未校验」。
