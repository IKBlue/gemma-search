【2. 字段与"为什么"（照抄设计基线 §222 + §234-241 的「附加」）】
| 表 | 字段 | 类型/约束 | 为什么（照抄基线） |
|---|---|---|---|
| `collection` | `collection_id` | TEXT **PK** | nanoid |
| | `name` | TEXT NOT NULL（**不 UNIQUE**） | 基线原话：「**不加 UNIQUE** —— 同名集合合理（去年与今年的提案可以同名）」 |
| | `note` | TEXT **NULL** | 集合级备注（可空） |
| | `created_at_ms` / `updated_at_ms` | INTEGER NOT NULL | 创建 / 修改时刻 |
| `collection_item` | `collection_id` | TEXT NOT NULL FK collection **PK(1/2) CASCADE** | 集合 |
| | `uid` | TEXT NOT NULL FK asset.uid **PK(2/2) CASCADE** | 条目 |
| | `added_at_ms` | INTEGER NOT NULL | 加入时刻，**也是默认排序键** |
· §240「`PRIMARY KEY (collection_id, uid)`」= 「集合里有哪些」+ **防重复加入**；§241「`idx_collection_item_uid (uid)`」=
  「这条被哪些集合收了」——**详情页要显示**。两条都已落地并被 C1/C8 机械钉住。
· ⚠️ `name` **不 UNIQUE** 是**反向**证明的（C2）：两个**同名**集合必须都能建出来 —— 谁"好心"加 UNIQUE，C2 会在
  `UNIQUE constraint failed: collection.name` 上红（§8 的注入③正是如此）。
· ⚠️ 两列**显式 NOT NULL**：SQLite 的 rowid 表里复合主键列默认允许 NULL ⇒ 不留神能插进 `(NULL, uid)` 的"无主成员"，
  还能重复插（NULL 互不相等）。C5 用 `PRAGMA table_info` 钉住。

【3. 顺序语义怎么落地（基线**没有** `sort_order` 列 —— 不造字段）】
· 顺序 = `added_at_ms` **升序**（基线：它是默认排序键）+ **`uid` 平局裁决**。
· ⚠️ 为什么必须有平局裁决：只按 `added_at_ms` 排序时，两条**同一毫秒**加入的条目顺序由 SQLite 的返回顺序决定
  （不保证稳定）⇒ 用户会看到"集合里的顺序自己变了"。加 `uid` 之后是**确定性**的。
· C3 机械证明三件事：① 顺序 = `added_at_ms` 升序；② **重复查询结果一致**（稳定）；③ **同一毫秒**的两条由 `uid` 定序且两次一致。

【4. ⚠️ 与标签的边界（**基数相同、顺序不同** —— 诚实的版本）】
| | `asset_tag`（B2-7a） | `collection_item`（本卡） |
|---|---|---|
| 主键 | `(uid, tag_id)` | `(collection_id, uid)` |
| 基数 | **N:M**（同条可挂多标签） | **N:M**（同条可进多集合 —— C3① 钉住了；卡面写的"1:N"在**基线**里其实不成立） |
| 顺序 | **无序**（顺序没有意义） | **有位置**：`added_at_ms`（+ uid 平局）是集合内容的一部分 |
| 位置的归属 | —— | **每个集合各自**：同一条素材在集合 A 第 3 位、在集合 B 第 1 位，互不影响（C3⑤） |
⇒ 结论：**别用"一个 N:M、一个 1:N"糊过去**；真正的差别是**顺序语义**与"位置的归属"。这也是 §0「不许把两处各写一半」的一种：
  卡面的措辞与基线字段表不一致时，**以基线/SPEC 为准**，并把这个差别写进注释（`T_COLLECTION`）与测试（C3）。

【5. 删除语义（逐条给理由 · C4）】
| 删谁 | item 行怎么办 | 理由 |
|---|---|---|
| 删**集合** | **CASCADE**（只有它的成员走，别的集合不受影响） | item 只是"哪条在哪个集合里的第几位"；集合没了，这个位置没有指代对象 |
| 删**素材** | **CASCADE**（它在**所有**集合里的 item 都走） | 素材没了，成员资格没有意义 |
| 为什么不用 SET NULL | —— | `(collection_id, uid)` 是复合主键、两列 NOT NULL ⇒ SET NULL 会写成非法值（被约束拒）；`(NULL, uid)` 这种"悬空成员"本身没有语义 |
· C4 用"**没有 NULL 残留**"排除 SET NULL（不只断言"是 CASCADE"）；并反证非法引用被 `FOREIGN KEY constraint failed` 拒。
· ⚠️ **代价如实写**：删素材会**连带**丢失它在各集合里的位置（顺序信息）。这是基线指定的 CASCADE 语义；
  要保住"曾经的位置"需要软删除/审计表 —— 后续卡的事，本卡不加（已写进 `T_COLLECTION` 注释）。
