【1 改前 → 改后 → 为何非放宽】
===============================================================================
1.1 形态
  改前：文件**无任何 export**；模块级（旧 139-174 行）解析 argv 得到 MODEL_DIR/LIB_ROOT/OUT_DIR/…，
        缺参就 process.exit(2)；末尾 `main().then(...)` 在**顶层直接执行** ⇒ import 即跑 CLI。
  改后：`export async function buildIndex(opts)`；模块级只剩纯常量与纯函数；
        CLI 参数解析在 `parseCliArgs`；末尾按 `pathToFileURL(process.argv[1]) === import.meta.url` 判定后 `runCli()`。
  为何非放宽：手工用法与输出**逐字保留**（§2），只是执行入口从「模块顶层」挪进「函数 + 守卫」；
        新增的进度/取消/写者都**只加信号**，不动产物（§3 逐字节对照）。
1.2 进度
  改前：只有 log()。改后：`onProgress({ phase, done, total, reused, failed, rate, etaSec })`，
        phase ∈ scan|uid|selftest|model|encode|persist|done ⇒ 正好对应 job 表的 progress_done/total/phase。
  为何非放宽：本卡**不落库、不接契约**（IDX-2 才做）；回调抛异常被吞掉（进度是旁路），不影响构建结果。
1.3 取消
  改前：没有。改后：`signal`(AbortSignal) + 检查点（开始 / 每条之前 / 落盘之前），抛 `BuildCancelledError`。
  为何非放宽：取消**明确抛**，不静默返回半成品；预置取消时**连 outDir 都不建**（测试断言）。
1.4 写路径（P1）
  改前：`writeIndexBin(file, header, vectors, count, dim)` 一把抓（组装 + tmp/fsync/rename）。
  改后：`buildIndexBinBytes`（**纯**组装）+ `writeIndexBinFile`（默认写者）；persist 走 `writeIndex` **注入点**。
  为何非放宽：产物字节逐字节相同（§3）；写者只剩一份实现（`writeIndexBin` 定义数 = 0，见 §7 G8）。
  ⚠️ 与本卡第 3 条的偏差需要你判定 —— 见 §8。

【8 ⚠️ 需要你判定的一条：卡片第 3 条「复用 writeIndexAtomically」】
===============================================================================
事实（file:line）：
· apps/desktop/src/main/index-file.ts:277-291：`writeIndexAtomically(libraryRoot, bytes, opts)` 的落点**写死**为
    `assertWritableGsPath(root, indexPathFor(root))` = <库根>/.gs-index.bin，且 `WriteIndexOptions` 没有 target 参数
    ⇒ 它**无法**写 <outDir>/index.bin。
· CLI 的 `--out` 是**构建暂存目录**（如 data/idx-full-v2），不是库根；两者不是同一个落点。
· packages/indexer 若 import apps/desktop/src/main/**，会把「包 → 应用」的依赖方向倒过来
    （PLAN.md:122 把 indexer 列为「原样保留」的独立脚本，就是因为这个方向）。
我的处理：给出**注入点** `writeIndex`（本卡能做的最大程度），并在两处 JSDoc 写明
  「主进程侧不要用默认写者写库根，必须注入 writeIndexAtomically」；CLI 默认写者保持原实现 ⇒ 产物逐字节不变。
  注入点**确实被调用**这一点已被证明（§3 的 WRITER_CALLS 与 §5(d) 的能红）。
建议（IDX-2 时二选一，都需要动 main/** ⇒ 不在本卡写入范围，我按边界停手）：
  ① 给 writeIndexAtomically 增加 target 参数（或抽出一个中立的原子写原语给两侧共用）；
  ② 由主进程这样调用：buildIndex({ …, writeIndex: ({ bytes }) => writeIndexAtomically(libRoot, bytes) })。
