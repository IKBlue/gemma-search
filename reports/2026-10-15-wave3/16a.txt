===== 7. 结论 =====
① 端口纯类型、实现在 main：`StoragePorts = { items?, index?, libraries? }`，三项互相独立、都可选。
   · ① 条目：`getItem(libId, uid)` / `listItems(libId)`
   · ② 向量索引：`readIndex(libId)` → `<库根>/.gs-index.bin`（实现应复用引擎 readIndexBin ⇒ 五道校验只有一份）
   · ③ 库解析：`LibraryResolverPort = EngineRegistry + storageOf(libId)`（复用既有概念，不另造一套「库从哪来」）
② 不注入 ⇒ 与改造前**逐字一致**：既有 158 条引擎用例一条没改就全绿，且 T16-P1 断言返回行里
   `hasOwnProperty('storage') === false`、`failed` 仍是数字。
③ 注入 ⇒ 走端口且**行为等价**：T16-P2 用同一份库、同一批请求对两条路做 deepEqual
   （results / libsUsed / libsSkipped / item / itemPaths / scan 全部逐字相同），并用 spies 证明
   readIndex / listItems / getItem **真的被走到**。
④ 不假绿：索引读不到 ⇒ `problems[0].code === 'INDEX_MISSING'` 且理由里带具体落点，`healthy=false`；
   条目端口抛错同理；新布局的 `failed` 报 **null（未知）** 而不是 0。
⑤ 门禁：引擎单独 tsc EXIT=0 · 项目 tsc 0 条 · 引擎单测 166/165/0/1 · 全仓 npm test 445/444/0/1（EXIT=0）

===== 8. 本轮发现 =====
A. ⭐ **T16-P7 抓到一个真 bug（新布局下才会暴露）**：`doScan` 的 walk **不跳过库内产物**，
   而新布局把 `.gs-index.bin` / `.gs.db` / `.gs-staging/` 放在**库根** ⇒ 它们会被报成「新增素材」。
   这是**假发现且不报错**（正是最难查的一类）。已修：walk 里用 U11 的唯一判据 `isReservedLibraryName`
   跳过库内产物，另按 SPEC §1 跳过隐藏项。
   原始失败输出（修之前）见下方第 9 节。
B. ⚠️ **既有行为（不在 T-16a 范围，如实上报）**：`scan` 的 `new` 里**一直包含压缩包**
   （`CR/c.zip` / `CR/d.7z` / `VR/a.rar`）—— 因为 items 只登记图。改造前就如此，
   T16-P2 的等价性用例（两条路 deepEqual）可证。T16-P7 已把这条**钉住**（免得被误当成 T-16a 的产物）；
   要不要把「压缩包不算新素材」改成体检口径，属 T-33。我没有顺手改 —— 那会改掉旧布局的可观测行为。
C. ⚠️ **端口抛错的契约**（实测后写进 storage-ports.ts 文档 + 用例钉住）：
   · `indexStatus` 用 `codeOf()` 读**任何**对象的 `code` ⇒ 抛带 code 的普通 Error 也能如实报出；
   · 但走**信封**的方法（search/scan/item）只在错误是引擎 `EngineError` 时保 code，其余归 `INTERNAL`。
   ⇒ 端口实现**应当**抛引擎错误（`fail(ERR.INDEX_MISSING, …)`）；main 复用 readIndexBin 时天然如此。
   初版测试用普通 Error，T16-P4/P8 当场红（`INTERNAL` vs `INDEX_MISSING`/`LIB_NOT_FOUND`）—— 这条差异因此被写成了明文契约。
D. `failed: null`（新布局）vs `0`（旧布局）：新布局里「失败项台账」不在这三个端口里（属 T-16b/T-33）。
   用 0 会被读成「没有失败项」= 假绿 ⇒ 报 null（未知）。旧布局形状不变。
E. `storage` 块（库根 / indexPath / dbPath / journalPath / indexExists / dbExists）**只在库解析端口存在时**出现。
   它**不参与 healthy 判定**：数据可用性以端口为准（端口读得到就是可用，读不到会在 problems 给理由）。
F. 夹具抽取：engine.test.mjs 与 storage-ports.test.mjs 共用 `tests/helpers/lib-fixture.mjs`
   （P1：同一份库的构造只留一份，否则「两种接线等价」的前提就不成立）。`MAGIC` 从 `src/index.ts` import，不另抄常量。
G. 未做（留给 T-16b）：main 侧端口组装、`.gs.db` 真正接上、M0 端到端；引擎侧**不接线**是本任务的边界。
