【实现要点（为什么这么写）】
1) 落点：indexPathFor(root) = path.join(path.resolve(root), GS_INDEX_NAME) —— 文件名**只有一份来源**
   （storage-roots.ts:49 的 '.gs-index.bin'），本模块不写第二遍字面量。
2) 原子写入：库根内临时名 <库根>/.gs-index.bin.tmp-<pid>-<seq> → 写 + **fsync** → （默认）五道校验 → rename 覆盖。
   · 为什么 fsync 写进端口契约：rename 之前数据必须真落盘，否则掉电会留下"名字对、内容是半截"的索引 ——
     那正是原子写入要防的东西。
   · 为什么 rename 之前要校验（默认开，validateBeforeRename=false 可关）：rename 是本模块**唯一不可逆**的一步；
     拿引擎的五道校验验过临时文件再覆盖，就能做到"宁可不写，也不用一份坏 buffer 盖掉好索引"。
     代价是多读一遍 11 MB，相对一次索引构建可忽略。
3) 读取：**复用引擎 readIndexBin**（五道：MAGIC / footer 解析 / footer.complete / count-dim 一致 / sha1）。
   本模块不碰字节格式，也不做"轻量版校验"（第二份解析 = P1；轻量版会让"损坏"退化成"看起来还行"）。
   失败抛的是**引擎的 EngineError**（INDEX_MISSING / INDEX_CORRUPT）原样透传 —— code 与 userMessage 归引擎契约，
   这里包一层只会逼调用方再映射回去。
4) 只写 .gs-*：assertWritableGsPath 机械拦住两件事 —— 目标必须是库根的**直接子项**（所以 ../ 穿越与子目录都被拒），
   且名字必须匹配 .gs-（点前缀 + 至少一个字符 + 不含路径分隔符）。写入前对目标与临时名各断言一次。
5) **不建库根**（你的 U6 裁定）：库根不存在就报 INDEX_WRITE_FAILED，不顺手 mkdir。
6) 错误码：INDEX_ROOT_REQUIRED / INDEX_BYTES_REQUIRED / INDEX_PATH_OUTSIDE_GS / INDEX_WRITE_FAILED；
   失败消息里**必须**带临时文件的清理留痕（'已清理临时文件 …' 或 '⚠️ 临时文件未能删除 …'）。
7) 0 字节与非法类型在**写之前**就拒（INDEX_BYTES_REQUIRED）：0 字节文件必然过不了五道校验，
   别给它机会先盖掉一份好索引。
8) fs 走可注入端口 IndexFs（5 个能力）；读路径固定用真实 fs（解析与校验都在引擎里，注入没有意义）。

【这条测试**证明不了**什么（如实写）】
· 不证明"掉电时一定安全"：fsync + rename 是**正确的做法**，但本机没有断电注入，测不了断电语义。
  能证明的是：目标名上永远只出现完整文件（临时名 → rename），以及失败路径不留临时文件。
· 不证明真实磁盘满（ENOSPC）：没有可靠的造盘满手段；写入失败那条分支是用注入 fs 的 L4c 覆盖的（校验失败 + unlink 失败）。
· 不涉及**谁来生成**索引字节：本模块只管"把给定字节原子地放到库根"。索引内容的构建属 packages/indexer（T-13/T-16）。
· 未接线 ⇒ 启动流程/界面还不认识这个模块（T-15/T-16 负责）。
