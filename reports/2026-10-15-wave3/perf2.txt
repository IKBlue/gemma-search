### 0.2 修复：E9-a 不再用"读一眼就分叉"（本卡第 2 件）
`apps/desktop/e2e/item-detail.spec.mjs` 原判据：
~
const fallback = win.getByTestId('image-fallback');
const img = win.locator('img').first();
if (await fallback.isVisible().catch(() => false)) {   // ← 单次瞬时读，不重试
  …断言兜底文案…
} else {
  expect(await img.getAttribute('src')).toBe('thumb://L1/a00000000001@512');
  //   ↑ 这一支**假设 <img> 还在**：若那一眼读完之后 img 才被兜底换掉，就会去等一个不存在的元素
}
~
⇒ 这是**依赖固定时序**的判据（"读那一眼"落在哪一侧决定成败），不是"超时太短"。
修复：把分支改成**等图片区进入确定的两种形态之一**（就绪标记），并且**用轮询落定的那一刻观察到的值**断言，
不再重新去读一个可能已经消失的元素：
~
let imageState = 'pending';
let imgSrc = null;
await expect
  .poll(async () => {
    imageState = 'pending'; imgSrc = null;
    if (await fallback.isVisible().catch(() => false)) { imageState = 'fallback'; return imageState; }
    imgSrc = await img.getAttribute('src').catch(() => null);
    if (imgSrc) { imageState = 'img'; return imageState; }
    return imageState;                       // ← 两个都还不是 ⇒ **继续等**，而不是就此分叉
  }, { timeout: 20_000, message: '图片区既没进兜底、也没出现带 src 的 <img>（未就绪）' })
  .not.toBe('pending');
~
**验证**：`item-detail.spec.mjs` 单跑 **6 passed (15.6 s) · EXIT=0**（修复后实测）。

3. ⚠️ BUILD-2 的教训：一个模块只能走一条腿（这次是"搬家"）
================================================================
`SearchPage` 从「动态」改成「静态」**必须两处同时改**，而且它**只能出现在一处**：
· `router/index.tsx` ⇒ 静态导入（它是唯一引用它的地方之一）；`main.tsx` ⇒ 从 `ROUTE_PAGES` 移入 `STATIC_PAGES`。
· **如果只改 router、不把它移出 `ROUTE_PAGES`**：它会同时是"动态（glob）+ 静态（import）"
  ⇒ **BUILD-2 修掉的 19 条那类警告立刻回来**（就是 BUILD-2/PERF-1 反复踩的那个坑）。
· **如果只改 main.tsx、router 仍 lazy**：它就是"静态（glob eager）+ 动态（lazy）"，同上。
⇒ 本卡的验收里 `警告 = 0` 正是这条的**机械检查**（见 §4 的构建输出）。
