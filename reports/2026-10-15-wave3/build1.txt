5. S10：bmp_decode 双 import
================================================================
【事实】`apps/desktop/src/main/encoder.ts` 同时 **静态**导入（顶部：`readFileHead / isBmpHead / HEAD_SNIFF_BYTES`）
和 **动态**导入（`readImageAny` 的 BMP 分支：`await import(…/bmp_decode.ts)`）同一个模块。
Rollup 因此警告：
~
(!) packages/indexer/src/bmp_decode.ts is dynamically imported by …/encoder.ts but also statically imported by
    …/encoder.ts, dynamic import will not move module into another chunk.
~

【保留哪种 · 理由】**保留静态、删掉动态**：
· 模块在文件顶部**已经被静态导入**，而那几个头读函数是"每次读图"的必经路径 ⇒ `bmp_decode.ts`
  **本来就在主 chunk 里、早就求值过了** ⇒ 那个"延迟加载"**一点延迟都没省下**（Rollup 的警告说的就是这件事）；
· 所以动态 import 只保留了一个**错觉**。删掉它 = 少一次无意义的 `await`，**语义不变**；
· 反过来（删静态、全动态）会动到热路径（`readHead` / `isBmpHead` 是同步调用），代价大、收益只是
  "首屏晚一点加载整个 bmp_decode" —— 那属于另一次有取舍的改动。代码注释里写明了这一点，
  并留了一句"将来真要做，必须连头读函数一起改成动态，不要只在调用点做半套"。

【效果】构建警告 **20 → 19**，`bmp_decode` 那条 **GONE**：
~
[ctrl-default]   warnings=1    bmp_decode present = true     ← 改前（那时渲染层还没跑到）
[after-A-default] warnings=20  bmp_decode present = true     ← 修 S10 前
[after-S10-fix]   warnings=19  bmp_decode present = false    ← 修 S10 后
~
⚠️ 剩下 19 条是**渲染层**同类警告（`ui/*.tsx` / `pages/*.tsx` 被 `main.tsx` 动态导入、又被
`App.tsx` 或彼此静态导入）。那些文件**不在本卡写入范围**，见 §7.3。

9. 环境说明（是环境还是产品）
================================================================
· 本机沙箱对 `%TEMP%` 下 esbuild 临时目录的 **`remove` 拒绝**（`Access is denied`）—— **环境**；
  产品侧的问题是"**依赖**了这台机器的环境"，那才是本卡要修的，且已修（构建不再读系统临时目录）。
· 顺带实测一条**通用结论**（写进配置注释了）：Node 的 `os.tmpdir()` **不缓存** ——
  先调用一次、再改 `process.env.TEMP`，下一次调用就返回新值（实测 `before: C:\…\Temp` →
  `after: D:/__probe_tmp`）。所以"在配置文件里改 env"这条路径确实生效。
· dev / preview **刻意不重定向**：那两段由 electron-vite 拉起 **Electron**，子进程会继承这份环境；
  那时改 `TEMP` 等于把 Electron 自己的临时目录（GPU 缓存 / 崩溃转储 / `app.getPath('temp')`）
  搬进仓库 —— 那才是真的行为改变，而 dev 不需要这条修复。
· `data/_esbuild-tmp` 是 `data/_*` ⇒ 已被 `.gitignore:25` 与 `.prettierignore` 覆盖，不入库、不被格式化。

—— 原始输出文件：`data/_build1/{ctrl-default,after-A-default,after-B-repo-tmp,after-C-bogus-tmp,after-D-only-tmp,
   after-S10-fix,canred-disabled-bogus-temp,baseline-before,baseline-after}.txt`（PowerShell `Tee-Object`
   默认 UTF-16LE，读的时候注意编码）。
