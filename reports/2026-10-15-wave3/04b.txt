【接线方式】index.ts 的 app.whenReady() 里，buildEngine() 之后调用 logStorageRoots()：
  · 程序目录 = app.isPackaged ? path.dirname(app.getPath('exe')) : ROOT（SPEC §2 的「程序目录」）
  · userData  = app.getPath('userData')（**仍然可由 --user-data-dir 覆盖**，未改）
  · 库列表    = librariesResolved().libraries（**仍然是 library-config.ts 的四条路**，未改）
  · 用户指定模型目录 = config.onnx_model_dir（既有字段）
  然后逐行 log() → 落进 GEMMA_APP_LOG 指定的日志文件与 stdout。
  **只记录，不改变任何行为**：库从哪来、模型实际用哪个都不受影响。
  另并列打出 resolveModelDir() 的真实返回值（T-17 才收敛那条 model_cache 路径），
  目的是把「SPEC 搜索顺序」与「实现实际用的目录」的差异**摆在明面上**而不是藏起来。

【三种情形的实跑结果（真 Electron，日志原文见「命令 6」）】
  情形 A 程序目录可写（app/models 里有 onnx/model.onnx）
    → 模型 = <app>/models（来源：程序目录 models/）；库根可写 → 落点 = 库根本身
  情形 B 程序目录不可写（对 <app>/models 加 icacls 拒绝写）

  情形 C 库根不可写（对库根加 icacls 拒绝写）

  情形 D 三位都没有模型
    → 模型 = **未找到** + 逐条列出找过的路径 + 放法 + 「找到之前不会显示任何检索结果」
  另: 情形 E = 不加任何 GEMMA_* 覆盖跑真应用（见「命令 7」）：
    引擎就绪 · 库 L1=G:\model[index-meta] —— data/libraries/* 自举这条路没被动；
    注册表路径 = <userData>/library-registry.json —— 未被动。

【⚠️ 环境噪声判定：G:\model 的 EPERM 是**本会话沙箱**造成的，不是产品事实】
  情形 E 里 [存储] 报「库根不可写 ⇒ 回退 userData（G:\model EPERM）」。逐层查证（原始输出见「命令 8」）：
    · 普通 node 写 G:\model\xxx  → **OK**
    · 同一个 electron.exe 的正常浏览器进程写 G:\model\xxx → EPERM
    · 同一进程写 C:\Users\...\AppData\Roaming\Electron\xxx → EPERM
    · 同一进程写仓库内路径 → **OK**
  ⇒ 本 agent 会话的文件沙箱把 electron.exe 的写限制在**仓库工作目录内**，仓库外的路径一律 EPERM。
    这与 G:\model 自身的权限无关（icacls 显示 Authenticated Users:(M)，普通 node 也能写）。
    ⇒ 因此「库根不可写 ⇒ 回退 userData」这条规则**不能**用 G:\model 当证据；
      有效证据是情形 B/C —— 那两处用的是显式 icacls 拒绝，且**普通 node 同样被拒**（见 04a.txt 命令 4 同款实验），
      与沙箱无关。
    ⇒ 在真实用户环境（无本沙箱）里，G:\model 是可写的，落点会是库根本身。**不要把 E 的日志读成"G:\model 坏了"。**

【残留检查】所有情形跑完后，data/_t04 与真实库 G:\model 下都**没有** .gs-write-probe-* 残留
  （探测文件写完即删；库根下也没有任何 .gs-* 被创建）。

### 命令 9 · 把「ACL 拒绝」与「会话沙箱」两件事分开（证明情形 C 的证据是 ACL 而不是沙箱）
目录在仓库内（沙箱允许写），只由 icacls 拒绝当前用户写。
PS> icacls data/_t04/acl-check-lib /reset ; node data/_t04/_aclcheck.cjs data/_t04/acl-check-lib
  普通 node 写 -> OK
PS> icacls data/_t04/acl-check-lib /deny "$env:USERNAME:(W)" ; node data/_t04/_aclcheck.cjs data/_t04/acl-check-lib
  普通 node 写 -> EPERM
  ⇒ 普通 node 也被 ACL 拒绝写 ⇒ 情形 B/C 用的 icacls 拒绝是**与沙箱无关**的独立证据。
PS> icacls data/_t04/acl-check-lib /reset   （还原）
  普通 node 写 -> OK
