2. 界面 ↔ 事件流 对应关系
================================================================
| 界面元素 | 数据来源 | 备注 |
|---|---|---|
| 阶段（扫描/配对/编码/校验/落盘） | `index.progress.phase` → `store/tasks.ts` 的 `phaseLabel` | 认不出的 phase **原样显示**（不猜） |
| 已处理 / 总数 | `index.progress.done/total` | ⚠️ total 只认 progress；`indexStart.total=0` **不参与显示** |
| 百分比 / 进度条 | `progressPercent({done,total})` | total 未知 ⇒ 返回 null ⇒ **不画**百分比（不确定进度条），不编数 |
| 速率 / ETA | `index.progress.ratePerSec / etaSec` | 引擎没给 ETA ⇒ 显示「—」，不估算 |
| GPU 回退公告 | `index.progress.deviceFallback` | 一旦出现就留到任务结束（契约 §3 要求界面必须显示） |
| 续跑说明 | `index.progress.note` | 如"复用 N 条（compat 相符）" |
| 终态：完成 | `index.done` → `outcomeSummary` | 复用 N · 新编码 M · 失败 K |
| 终态：已取消 | `index.done{cancelled:true}` | 显示"停在 N 条；索引文件未写入" |
| 终态：失败 | `index.failed` | 原样显示引擎的 userMessage；**不编兜底文案**（layering L6） |
| 取消按钮可点性 | `store.running` | 无任务时 **disabled**（不是点了才发现没任务） |
| 操作错误（IPC 层） | `useIndexTasks` 的本地 state | 与"任务失败"分开：一个是发起失败，一个是跑到一半失败 |

（或者给假构建器加个"慢一点"的开关，但那要动 main/注入，超出本卡写面。）
