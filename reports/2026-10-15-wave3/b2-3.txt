【2. 字段出处（照抄设计基线）】
出处 = `reports/2026-10-15-schema-diff/SPEC-COMPACT.md` §「asset_user_meta [本轮] · 字段 5」（第 179-187 行）。
| 字段 | 类型/约束 | 为什么（照抄基线） |
|---|---|---|
| `uid` | TEXT **PK + FK asset.uid ON DELETE CASCADE** | **1:1**；没有行 = 还没被标注过（**合法状态，不是缺失**）；素材真被删 ⇒ 标注跟着走 |
| `rating` | INTEGER NULL **CHECK 1..5** | **用 NULL 表示未评分，不用 0** —— 0 会让人分不清"没评"与"评了 0 分"，而后者**语义上不存在**；范围写进 CHECK |
| `note` | TEXT NULL | 自由备注，**不设长度上限**（截断是界面的事，不是存储的事） |
| `updated_at_ms` | INTEGER NOT NULL | 最后编辑时刻 |
| `is_favorite` | INTEGER NOT NULL DEFAULT 0 **CHECK 0/1** | 收藏是**一列布尔**而不是一张关联表：比特级的用户意图，且"筛收藏"是高频查询 |
索引：基线在 `is_favorite` 的约束列里点名要"**偏索引** `WHERE is_favorite = 1`"（**只给谓词、没给名字**）
  ⇒ 本仓命名为 `idx_meta_favorite`（M1 断言它 `partial = 1` 且列就是 `is_favorite`）。
  ⚠️ 名字是**本仓定的**（基线没规定名字）；谓词与列是基线规定的。这一点写清楚，避免"看起来像自造"。
