## 0. 结论（一句话）
  E9-a 的间歇红**不在产品里**，在**这条判据自己**：图片区的"两种形态之一"是用 Playwright
  **locator** 读的，而 locator 调用带**自动等待** —— 一旦 <img> 已被兜底换掉，
  `img.getAttribute("src")` 就会为这个**已经不存在**的元素等满 action timeout（30 s），
  而 `expect.poll` 的预算只有 20 s ⇒ **第一轮就吃光预算，"重试"从来没发生过**：
  判据实际仍取决于第一眼那一瞬，只是把 8af6365 的"单次瞬时读"换了个形式。
  ⇒ 修法：poll 的每一轮改成 **一次 page.evaluate 的纯 DOM 读**（无自动等待、无 strict mode），有界、可重试。

## 3. 根因（为什么读不到第二次）
  失败版 poll 的一轮：
    ① if (await fallback.isVisible().catch(() => false)) → 第一眼时兜底还没画出来 ⇒ false
    ② imgSrc = await img.getAttribute("src").catch(() => null)   ← **就在这里挂住**
       <img> 已经不存在 ⇒ locator 自动等待直到 action timeout（30 s）；
        而 poll 自己的 timeout 是 20 s ⇒ 报「未就绪」时，其实第一轮还卡在第 ② 步。

## 4. 修复（只改判据，不碰产品代码、不加 retries、不调超时）
  改前：poll 内用 locator 读（fallback.isVisible / img.getAttribute）—— 带自动等待
  改后：poll 内一次 win.evaluate 纯 DOM 读：
        const s = await win.evaluate(() => { ...visible(fb)... imgEl.getAttribute("src") ... });
        if (s.fallbackVisible) → fallback； else if (s.imgSrc) → img； else → pending（继续等）
  为何非放宽：**断言一字未改** —— 仍然是"两种形态必须其一"，仍然断言兜底的两条精确文案
    「无预览」「文件可能已不在盘上」、仍然断言 `thumb://L1/a00000000001@512` 这个**精确** src；
    改的只是"怎么读"（有界、可重试），以及失败时 dump 现场。
  顺带删掉一个已不再使用的 locator 常量（eslint no-unused-vars 抓出来的）。

## 7. Lead 的怀疑：把 `data/_e2e-tmp` 集中 = userData 共用 / 单实例锁撞车？—— **不成立**（实测 + 代码）
  · **每次启动的 userData 都是唯一的**：helpers/launch.mjs 用 fs.mkdtempSync(E2E_TMP_ROOT, "launchapp-")
    （app.mjs 的三个场景 helper 走 tmpDir(tag) 同样唯一）⇒ `requestSingleInstanceLock()` 按 userData 计，
    **不同 spec 之间不可能撞**；`data/_e2e-tmp` 只是父目录，子目录互不复用（mkdtemp 不复用已存在的名字）。
  · 症状也不对：锁没抢到的表现是**窗口根本不出现**（firstWindow 超时），而 E9-a 失败时
    **窗口/标题/元数据/动作区全在**（§2 的 DUMP）—— 不是"卡在启动"，是"卡在一次读"。
  · `.gs.db`/WAL 残留也不适用：E9-a 跑在**模拟模式**（库根 Z:\__fake_library__ 不存在，不写盘）。
  · 结论：这条线索方向优雅但被证据否掉了；真因是判据里的自动等待（§3）。
  ⚠️ 这不等于"helper 的落点改动有问题"：START-1 的落点改动仍然必要（它把 6.1 s 的环境假象去掉了）。

## 9. 未决 / 如实边界（P6）
  · 这是一个**低频竞态**（旧版 2/6、8af6365 版约 1/8..1/25）⇒ 150 次干净 + 5 次全量全绿是**证据**，
    不等于"数学上不可能再犯"；但修后的判据**结构上不再有"自动等待吃光预算"**这一步，那一类失败被移除。
  · 我没有加 retries、没有改任何超时阈值；产品代码（main/** · renderer · shared · packages）**一行未动**。
  · 新增的 dumpImageArea 只在**失败路径**调用，不改变判据，也不影响通过时的行为。
