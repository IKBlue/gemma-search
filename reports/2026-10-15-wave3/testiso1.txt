## 0. 改前 → 改后 → 为何非放宽
  改前：log.ts 在**模块导入期**算出写死的 LOG_FILE，并立刻 `fs.writeFileSync(LOG_FILE, "")` **截断**
        <ROOT>/data/_app.log。⇒ npm test 里只要任何文件 import 到 log.ts（library-ipc 那条链），
        就会把 e2e 正在读的共享日志清空（WIRE-A 实测：START-2 收到的是 items-ipc/collect-ledger 的 argv 行）。
  改后：
   ① **导入期零文件 I/O**：import 只把头部行放进有界内存缓冲，不碰任何文件；
   ② **落点跟随调用方**：主进程 index.ts 用 `configureLogFile({ path: … DATA_DIR … })` 接线，
      日志落在 `<data_dir>/_app.log`；e2e 每个启动的 data_dir 都是独立临时目录 ⇒ **每个进程一份日志**；
      显式 `GEMMA_APP_LOG` 仍优先（排障/既有 spec 的覆盖口）；
   ③ **不截断**：打开时 `appendFileSync`，按需创建；配置前缓冲的头部行会按序刷进去（应用日志仍有启动头）；
   ④ 没配置的进程（单测）**一个字节都不写**（缓冲在退出时丢弃）。
  为何非放宽：这是**收紧**——旧行为"任何 import 都清空别人的日志"本身就是越界写；
        断言没被放宽（log-fallback 的"写不进去必须可见"一条没删，只是失败现在发生在 configure/append 时）；
        且新增了机械守卫（G1/G2/G3），改回去**必红**。

## 1. 实现（3 个产品文件 + 4 个量具/测试文件）
  · main/log.ts：删掉 `export const LOG_FILE` 与导入期 mkdir/writeFileSync；新增
      resolveLogFile() / isLogFileConfigured() / configureLogFile({ path })、appendLine()、PRELOG 有界缓冲；
      logStatus() 增加 configured / pending 两个字段（诊断仍能看到"该写哪儿/配没配"）。
  · main/index.ts：在算出 DATA_DIR 之后**唯一一处**接线
      configureLogFile({ path: process.env.GEMMA_APP_LOG || path.join(DATA_DIR, "_app.log") });
  · e2e/helpers/app.mjs：四个场景 helper 都暴露 `logPath: path.join(dataDir, "_app.log")`。
  · first-paint / perf / start1-probe：不再读共享 <ROOT>/data/_app.log，改读本次启动的日志
      （first-paint、start1-probe 用 helper 的 logPath；perf 用自己的 work/data 下的 _app.log）。
  · tests/log-fallback.test.mjs：L1/L2 按新口径重写（见 §3 的双向断言）。
  · tests/testiso1-log-guard.test.mjs：**新增守卫**（G1 行为 + G2 落点 + G3 源码/接线）。

## 2. 守卫写了什么（含"对象字面量调用"口径）
  G1 ⭐ 只 import 不配置 ⇒ 共享 <ROOT>/data/_app.log **逐字节不变**（子女进程实测，含 log() 调用）；
  G2 ⭐ configureLogFile({ path }) ⇒ 写到那个文件（含缓冲头部按序刷入），共享日志仍不动；
  G3 ⭐ 源码守卫：
     · log.ts（mask 注释后）不许出现 LOG_FILE 常量、不许 writeFileSync、模块顶层不许直接 fs.*；
     · index.ts 必须以 **configureLogFile({ path: … DATA_DIR … })** 的**对象字面量调用**接线
       （P8 教训：函数名出现在注释里不算证据）；
     · helpers/app.mjs 必须**四处**暴露 logPath: path.join(dataDir, "_app.log")；
     · first-paint / perf / start1-probe 不许再写死 path.join(ROOT, "data", "_app.log")。

## 3. log-fallback 的两条（失败可见性没被放宽）
  L1（新口径）：只 import 不配置 ⇒ 共享日志逐字节不变、configured=false、ok=true（没写就没失败）、log() 不抛。
  L2（保留原意）：把落点 configure 到"父路径是个文件"的位置 ⇒ logStatus().ok=false、failures>=1、
      stderr/stdout 有大声一行（/日志写入失败/ + /packed=/）、log() 不抛。
  ⚠️ 唯一变化：失败时机从"导入期"挪到"configure/append 时"—— 断言强度不变（仍是"写不进去必须可见"）。
