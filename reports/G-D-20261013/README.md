## 6. 双向验证（`bidirectional.md`）

判据：**把防线拆掉，断言必须变红。** 5 例全部呈现「注入 → 红 / 还原 → 绿」：

| 例 | 注入什么 | 注入态 | 还原态 |
|---|---|---|---|
| **IA1** | 把 `changed→stale` 提到 `exists→removed` 之前 | 9/10，**fail 1** | 10/10 ✅ |
| **T2** | 去掉 `done` 的 `Math.max`（进度不再单调） | 12/13，**fail 1** | 13/13 ✅ |
| **S13/S14/S16** | 插值处理后 `continue` → `i = j; break`（复现扫描器旧缺陷） | 14/17，**fail 3** | 17/17 ✅ |
| **S15** | `uid: Uid.optional()` → `uid: Uid`（undo 又变必填） | 14/15，**fail 1** | 15/15 ✅ |
| **E10-f** | 界面文案抄回引擎原文（断言靶子不再唯一） | **fail 1** | **pass 1** ✅ |

> 这 5 例里有 **3 例是"先写错、被双向验证抓出来"的**（T2 断的是最终值 ⇒ 拆掉守卫照样通过；
> S13/S14 用错了 `maskComments` 视图 ⇒ 失步在它眼里看不见；E10-f 靶子不唯一 ⇒ 假绿）。
> ⇒ 结论：**只写断言不做反向验证，无法区分"防住了"与"根本没测到"。**

## 7. 本阶段顺带修掉的两处真缺陷（都在上述证据里）

1. **共享扫描器「模板插值之后整段失明」**（`source-scan.mjs`）：处理完 `${...}` 后回主循环、没回模板串 ⇒
   收尾反引号被当成新模板起始，一路吞到文件尾。**双向后果**：① 假阴 —— `SearchPage.jsx:55+`、
   `TasksPage.jsx:76+` 等区域整段失明 ⇒ 基于它的 **L1–L7 / T1–T6 断言在那些地方恒为真**；
   ② 假阳 —— 注释里的反引号内容漏出（L6 曾被自己的注释绊倒）。回归锁：`S13/S14/S16`。
2. **E10-f 的"偶发失败"不是 flake**：`getByText(/这个功能还没做好/)` 同时命中界面空态提示与 toast
   （界面抄了引擎原文）⇒ 负载高时报 strict mode violation、负载低时只命中提示而**假绿**。
   已改为盯唯一的 `#toast` + 加回归断言。修复后**整套连跑两次均 `56 passed`**（此前 2/3 会挂）。
