# _archive / 被取代的原型

这里的文件**不再维护，也不该被当作现行设计**。留着是为了可追溯。

## 为什么归档

`static\prototype\` 是**现行原型套件**（6 页 + 共享 `style.css`/`app.css`/`app.js`）。
下面两份是它之前的两条方向，已被取代：

| 文件 | 是什么 | 被谁取代 | 归档理由 |
|---|---|---|---|
| `app-ui-mockup.html` | 单文件原型（浅色工作区 + 靛蓝强调） | `prototype\` 套件 | 单文件、无共享资源、只有一个文件承载全部视图 |
| `app-ui-v3-dark.html` | 单文件原型（**全暗色** + 深红强调，按 Arasaka 参考图） | `prototype\` 套件 | 与 `prototype\` 的"深色侧栏 + 浅色工作区"是**两条竞争方向**；同时留两套会让实现无所适从 |

## 为什么最终选了 `prototype\` 那套

1. **成套**：3 页已互相链接（`图库与索引任务.html#tasks` 等），是一个完整信息架构，不是单页。
2. **与最初表述一致**：你最早说的是"深色侧边栏、浅色主工作区"，`prototype\` 正是这套。
3. **可减债**：三页 CSS 逐字节相同（sha1 `543944ecb496`），抽共享文件是净减债；单文件原型没有这个空间。

## 但 v3-dark 里的两样东西**已并入现行套件**，不是丢掉

| v3-dark 的内容 | 现在在哪 |
|---|---|
| **图片详情**页（大图 + 元数据 + 动作按"是否需重编码"分区 + 危险区） | `prototype\图片详情.html` |
| **文件操作确认**弹窗（确切变更清单 + 可撤销性 + 空间核算） | `prototype\文件操作确认.html` |
| 卡片"图上覆盖标题条"的密度做法 | `prototype\app.css` 的 `.photo .overlay-cap`（备用） |

所以归档的是**外壳与配色方向**，其中的功能设计已经转移过来了。
