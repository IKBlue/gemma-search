文件操作确认

每条确认框必须回答四件事：改什么、改成什么、能不能还原、空间够不够。

点一个操作看它的确认框

确认框的硬要求（来自 SPEC-transactions / SPEC-identity）

要求说明
列出确切变更图与包逐条列出：源路径 → 目标路径、体积。含糊的"确定吗"一律不合格
标注可撤销性能否撤销、保留多久、过期后为什么不能撤销（保留期 / 空间回收）
空间核算目标卷可用量 vs 本次需要量；不足则在写任何文件之前拒绝
重编码提示复用向量 / 需重编码（约 0.42 s）必须显式区分
危险按钮用动词「确认移出库」而不是「确定」；实心填充 + ⚠ 图标，与强调色区分
不作数的情况重名冲突、ID 重复、compat 不一致 → 确认框里直接拦住，不给"仍要继续"
原型：按钮只弹提示，不会真的改动文件 写操作仅经事务执行器；其它代码不得直接 rename/unlink
