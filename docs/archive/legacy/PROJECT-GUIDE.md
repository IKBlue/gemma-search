# 项目结构总览 · 零基础版

> 这份文档写给**第一次打开这个仓库的人**，不需要懂 Node、Electron 或 AI。
> 读完你会知道：这个项目是干什么的、每个文件夹管什么、东西该放哪儿、以及为什么这么放。

## 1. 一句话说清这个项目

> **用中文说一句话，在你自己的电脑上找出最匹配的那张素材图，并告你它的模型压缩包在哪儿。**

比如输入「现代简约布艺沙发」，它不靠文件名、不靠标签，而是靠**「长得像不像」**：
把 3594 张预览图都变成一串数字（叫「向量」），把你这句话也变成一串数字，然后比谁的数字最接近。
图找出来了，同名 `.zip` / `.rar` 模型包的位置也就跟着找到了。

**三个关键约束**（决定了它为什么这么设计）：

| 约束 | 含义 |
|---|---|
| **全离线** | 不联网、不上传、不调用云服务。模型文件早就下到本机了 |
| **素材库在你自己盘上** | `G:\model`，3594 张图 + 3594 个同名压缩包，分 4 个类别文件夹 |
| **只读，绝不改你的素材** | 它只返回路径，不移动、不复制、不重命名、不删除 |

它是一个**双击就能打开的桌面窗口程序**（用 Electron 做的，和 VS Code 同一种外壳技术）。

## 2. 它长什么样、代码在哪

一个桌面应用由三层组成，本仓库严格分开：

```
     ┌──────────────────────────────────────────────┐
     │  界面（你会看到的部分）                       │
     │  搜索框 · 结果缩略图 · 进度条                 │  → src/renderer/
     ├──────────────────────────────────────────────┤
     │  安全桥（界面与引擎之间唯一的一条受控通道）    │  → src/preload/
     │  界面不能直接读你的磁盘，只能通过这里请求       │  → src/shared/ipc.mjs（契约）
     ├──────────────────────────────────────────────┤
     │  引擎（真正干活的大脑）                       │
     │  扫描素材库 · 编码 · 比向量 · 事务 · 指纹      │  → core/
     └──────────────────────────────────────────────┘
```

**为什么这么分？** 因为引擎必须能被单独测试，且**绝不依赖界面**——
所以 `core/` 是**零第三方依赖**的，只用 Node 内置能力。这样它才能：
① 被 68 个单测直接跑；② 将来换界面（比如换掉 Electron）而不用重写检索逻辑。

> 📌 **本仓库历史上曾有两套代码**（旧的 Python 档 + 新的桌面应用）同时存在。
> 2026-10-10 起 **Python 档已整体删除**，现在只有这一套。见 §7。

```
gemma-search\

│   ├── tests\                  引擎单测（node:test）
│   └── scripts\                启动辅助（解决 Electron 在本机的两个坑）
│
├── 🔵 【守门与质检 · 只读，随时可跑】
│   └── tools\                  6 个 Node 守卫 + Electron 启动探针
│
├── 🟣 【索引构建 · 离线实验室】
│   ├── onnx-spike\             ★ 唯一能建索引的地方（ONNX + WebGPU）
│   └── spike\                  当初「走哪条技术路线」的实验与证据
│
├── ⚪ 【产物 · 证据 · 原型】
│   ├── data\                   索引产物 + 运行日志 + 诊断中间物（**绝大多数不进 git**）
│   ├── reports\                门禁证据（无证据 = 门禁没通过）
│   ├── static\                 UI 原型套件（6 页）+ 设计令牌 + 计划总览页
│   ├── build\                  打包图标与 Apple 签名配置（**不是产物目录！**）
│   ├── out\                    构建产物（自动生成，不进 git）
│   └── archive\                被取代的旧计划与旧应用外壳（留档不删）
│
└── 📄 【文档 · 见 §5】
```

## 4. 每个文件夹：管什么、能不能动、进不进 git

**「进不进 git」很重要**：不进的就算你删了，别人克隆下来也没有——因为它们本该由脚本生成。

| 文件夹 | 一句话职责 | 你能改吗 | 进 git？ |
|---|---|---|---|
| `src\` | 新版应用界面与外壳 | ✅ 改（主战场） | ✅ 是 |
| `core\` | 搜索引擎本体，**零依赖** | ✅ 改（但要过 `npm test`） | ✅ 是 |
| `tests\` | 引擎单测 | ✅ 加测试 | ✅ 是 |
| `tools\` | 6 个 Node 守卫 | ✅ 改完自己跑一遍 | ✅ 是 |
| `scripts\` | 启动辅助（1 个文件） | ⚠️ 谨慎 | ✅ 是 |
| `onnx-spike\` | 索引构建器（`.mjs`） | ⚠️ 谨慎，动了要重建索引验证 | ✅ 是 |
| `spike\` | 路线决策证据（JSON 等） | ❌ **别删**，有 README 说明原因 | ✅ 是 |
| `archive\` | 历史留档 | ❌ 别删 | ✅ md/js 是 |
| `out\` | 构建产物 | ❌ **别手改**，`npm run build` 生成 | ❌ 否 |
| `data\` | 索引、日志、诊断中间物 | ⚠️ 只删 `_` 开头的 | 🔸 只有 `quality/`、`queries/` 是 |
| `reports\` | 门禁证据（**必须进 git**） | ✅ 加新证据 | ✅ md/json/csv 是，截图否 |
| `static\` | UI 原型 + 设计令牌 | ✅ 改原型 | ✅ 是 |
| `build\` | 打包图标 + 签名配置 | ⚠️ 别当产物删了 | ✅ 是 |
| `reference\` | 官方模型卡 | ❌ 只读 | ✅ 是 |
| `node_modules\` | 第三方库 | ❌ 别碰 | ❌ 否 |
| `.npm-cache\` | npm 下载缓存 | ❌ 别碰 | ❌ 否 |

## 6. ⭐ 新东西该放哪儿？（照这个表放，就不会满天飞）

**这是本文最实用的一节。** 想加东西时先查这张表。

| 你要加的是什么 | 放哪儿 | 注意 |
|---|---|---|
| 新的界面组件 / 页面 | `src\renderer\src\` | 页面放 `pages\`，通用组件放 `ui\` |
| 新的引擎能力 | `core\` | **必须零依赖**，且补 `tests\` |
| 新的契约 / IPC 通道 | `src\shared\ipc.mjs` | ⚠️ 这是**唯一来源**。改了它要同步 `src\preload\index.js`（那里目前是**手抄的字面量**，不是 import） |
| 新的守门 / 校验脚本 | `tools\` | 写完自己先跑一遍 |
| 一次性调查 / 探针 | `spike\` 或 `tools\probe_electron_start\` | 别放仓库根 |
| 被取代的旧东西 | `archive\` | 留档，别删 |
| 新的门禁证据 | `reports\G-<字母>-<日期>\` | **必须进 git**，否则算没通过 |
| 新的设计令牌 | `static\prototype\tokens.css` | 别复制第二份 |
| 新的规格 / 设计文档 | **仓库根**（`SPEC-*.md` / `DESIGN-*.md`） | 见下方说明 |
| 临时试验、日志、备份 | `data\_*` | 已 gitignore，随时可删 |

### 关于根目录那 13 份文档

**放根目录是刻意选择，不是乱。** 理由：它们是项目级权威文档，且全仓有 **200+ 处**引用
（代码注释、其他文档、脚本）。移动一次要改 200 处且极易漏。

**同类项目怎么做？** 见 §8——主流是把正文文档放 `docs\`。**如果你要改**，请作为**独立一次提交**来做，
别和其他改动混在一起，否则出问题无法二分定位。

## 7. 这个仓库最近发生了什么（读历史的人必看）

**2026-10-10 之前**：仓库里有**两套并存**的实现——
① 旧的 Python 档（命令行 / 网页 / MCP 接口，当时唯一在跑）；
② 新的 Electron 桌面应用（正在建）。

**2026-10-10 当天**：所有者决定新应用是唯一方向，**把整套 Python 档删掉了**（提前执行了计划里的 P7 退役）。

| 删了什么 | 数量 |
|---|---|
| 旧 Python 应用本体（`gemma_lib` / `cli` / `mcp_server` / `server` / `build_index` …） | 12 个 |
| `tools/` 下的 Python 守门与质量判据 | 20 个 |
| `spike/` 下一次性探针 | 16 个 |
| `archive/` 下旧脚本 | 4 个 |
| Python 专用配置（`requirements*.txt` / `start_server.cmd` / `config*.json`） | 5 个 |

**结果**：仓库里 **0 个 Python 文件**；仓库根从 40 个文件降到 **24 个**。

**代价（诚实记录，详见 `docs/DEBT-CLEANUP.md` §十二）**：MCP 工具失效、
**G-B 质量判据无法再复跑**（`reports/` 里的验收证据成为存档、不可独立复现）、
文档完整性 / 令牌纪律 / 语法体检 / 机密扫描四个门禁全部消失。
`npm test` 仍然 **68 项（65 过 · 3 跳过）**，所以**应用本身没被删坏**。

## 8. 同类项目对标（2026-10-10 调研）

调研了 11 个真实开源项目（immich 115.9k★ · anything-llm 66.9k★ · jan 44.9k★ ·
photoprism 40.3k★ · librephotos · manyfold · OpenAssetIO · clip-retrieval 等）。

| 我们的做法 | 同类项目怎么做 | 结论 |
|---|---|---|
| **引擎与界面分离**（`core\` vs `src\`） | 几乎**普遍**：immich = `server/`+`web/`+`machine-learning/`；librephotos = `apps/{backend,frontend}`+`packages/` | ✅ 我们的分层是对的 |
| **模型内置**（1.4 GB 下到本机） | immich / photoprism 都**让用户自己下载**，离线保证被削弱（immich 有大量「模型下不动」的讨论） | ✅ 我们的**离线完整性是相对优势** |
| **索引仅约 11 MB + 暴力余弦** | 多数项目上向量库（chroma / qdrant / FAISS / VectorChord） | ✅ 这个规模暴力更快更简单 |
| **配对显式存进索引**（`absPath` + `archiveAbsPath`） | manyfold 用「一文件夹一模型」；Blender 用旁挂 `blender_assets.cats.txt`；OpenAssetIO 用 trait | ✅ 我们比隐式约定更稳 |
| **长文档放仓库根** | 11 个样本里 **0 个**这样做，都去 `docs\` 或独立文档仓库 | ⚠️ **我们属于少数派**（见 §6 说明） |
| 新旧两套并存 | **没有样本用 `legacy\` 目录**；真实手段是并存 + 重定向表 / 变更日志 | ✅ 印证了「不建 `legacy\`」；我们最终选择直接删除而非并存 |

## 9. 常见困惑速查

**Q：仓库根为什么只有 24 个文件，但看着还是文档很多？**
A：13 份是**项目级权威文档**（规格 / 设计 / 验收 / 计划 / 债务账本），刻意放根目录且被 200+ 处引用。其余是配置与许可。

**Q：`data\` 里怎么这么多东西？能删吗？**
A：`data\` 下的东西**基本都不进 git**。规则很简单：**`_` 开头的一律是临时/派生文件，随便删**；
不带下划线的（如 `libraries\L1\`）是**当前正在用的索引**，别删。

**Q：索引为什么不在 git 里？**
A：它能重新生成，而且**含你这台机器的绝对路径**（`G:\model\...`）。别人克隆后自己建一份。

**Q：`G:\model` 是什么？为什么代码里不写死？**
A：那是**你自己**的素材库位置。代码里绝不写死本机路径，靠应用内的库注册表（`core/library.mjs`）管理。

**Q：`spike\` / `archive\` 看着像垃圾，能删吗？**
A：**不能。** 它们是「当初为什么这么选」的证据。每个目录里都有 README 说明了这一点。

**Q：代码里的 `mcp__gemma-search__*` 工具怎么不能用了？**
A：随 Python 档一起删了。需要等新应用提供等价能力，或从 git 历史里恢复旧档。

**Q：改坏了怎么办？**
A：`git status` 看改了什么，`git checkout -- <文件>` 撤销单个文件。

**Q：没有 Python 了，怎么还叫「gemma」？**
A：`gemma` 指模型 `google/embeddinggemma-2`，不是 Python 包。

## 11. 术语小词典

| 词 | 白话解释 |
|---|---|
| **向量 / embedding** | 把一段文字或一张图变成一串数字，让「意思相近」变成「数字相近」 |
| **索引 (index)** | 事先算好并存起来的向量集合。有了它，查询只需几十毫秒而不是几十分钟 |
| **引擎 (engine)** | 干活的「大脑」，不含界面。在 `core\`，故意不依赖任何第三方库 |
| **Electron** | 用网页技术做桌面窗口程序的框架（VS Code 同款） |
| **主进程 / 渲染进程** | 主进程管窗口与磁盘；渲染进程就是那个网页界面。两者严格隔离 |
| **preload / 安全桥** | 界面唯一能用的通道，只有 3 个函数，别的都够不着 |
| **IPC** | 主进程与渲染进程之间的受控通信 |
| **门禁 (gate)** | 一个必须通过的检查点 |
| **证据 (evidence)** | 门禁通过的凭据，存在 `reports\`。**没有归档证据 = 门禁没通过** |
| **契约 (contract)** | 接口的形状约定（有哪些方法、会报什么错）。先冻结，再写实现 |
| **设计令牌 (token)** | 颜色/字体/间距等视觉常量，集中一处定义，别在代码里写死 |
| **ONNX / WebGPU** | 模型的一种通用格式 / 让浏览器直接用显卡算的技术 |
| **配对 (pairing)** | 靠文件名主干相同，把 `ID-123.jpg` 和 `ID-123.rar` 认成一套素材 |
