### 0.1 spike 已跑完（2026-10-10）—— 后端定稿为 **Node + ONNX + WebGPU**

| 结论 | 证据 |
|---|---|
| 文本塔与 torch **bit-exact** | 余弦 **1.000000**（5 条中文查询，两个 seq 档都是） |
| 图像与 torch 差 **0.4%（中位）** | 来自预处理而非模型；**索引必须用同一运行时重建** |
| **WebGPU 可用且快** | 图像 **0.42 s/张 @seq140**（CPU 1.32 s；torch/GPU 0.16 s） |
| WebGPU **不引入额外漂移** | 其向量与 **ONNX CPU 小数点后 6 位一致** |
| DirectML **不可用** | `Reshape node_view_1` → E_INVALIDARG（结构问题，非精度） |
| CUDA **不支持** | `Unsupported device: "cuda". Should be one of: dml, webgpu, cpu` |
| **不需要 Python 了** | 打包从"5 GB 不可分发"变为"~200 MB + 模型"，可自包含 |

**因此新增一个前置任务（P0.5）**：用 ONNX 重建图像索引（约 25 分钟），并保留旧索引作对照。

## 1. 外壳选型：选 Electron

### 实测工具链

| 项 | 实测结果 | 对 Electron | 对 Tauri |
|---|---|---|---|
| Node / npm / pnpm | `v24.14.0` / `11.9.0` / `11.5.2` | ✅ 齐备 | ✅（前端需要） |
| Rust（rustc/cargo） | ❌ **未安装**（`.cargo` 目录不存在；PATH 里那条 `.cargo\bin` 是卸载残留） | 不需要 | ❌ **需先装 rustup**（约 1.5 GB + 构建链） |
| MSVC 链接器 | ✅ `14.44.35207`（VS2022 BuildTools） | 不需要 | ✅ 已具备 |
| WebView2 运行时 | ✅ `154.0.4258.62` | 不需要（自带 Chromium） | ✅ 已具备 |

### 决定性依据：外壳体积在这个应用里**几乎不重要**

**实测**：后端一个 Python+torch 进程常驻 **1719 MB**（`Get-Process` 实测），冷启动载模型约 **11 秒**。

| 指标 | Electron | Tauri | 差值占后端比例 |
|---|---|---|---|
| 安装体积 | ~150–250 MB | ~5–10 MB | 相对 4.35 GB 的 venv，可忽略 |
| 外壳常驻内存 | ~120–200 MB | ~40–80 MB | 相对 1719 MB，约 **5~9%** |

用一个进程 **5~9%** 的内存占比，去换：
- **多装一套 Rust 工具链**（当前没装）
- Rust 侧每次改动都要**重新编译**，而界面阶段会反复改
- 离线环境下更难核对 API（Electron 的类型定义装完就在本地，可直接读；Rust crate 文档要联网或靠编译试错）

### 结论

**选 Electron。** 本应用的成本与复杂度**几乎全在 Python + 模型侧**，外壳只做三件事：开窗、显示后端给的缩略图、调后端做"定位/取件/建索引"。为外壳省 100 MB 而引入 Rust 工具链与更慢的迭代，不划算。

### 什么情况下该改选 Tauri（保留重估条件）

1. 需要**分发给别人**、且要求小体积安装包 —— 但本应用不打包 Python（见规格 §3），分发本就受限，Tauri 的小体积优势无法兑现
2. 后端能改写成 Rust —— 不可能（依赖 torch/transformers/CUDA）
3. 若要坚持 Tauri：**第 0 步是安装 rustup**（需你批准，且首次编译较慢）。届时只有 `app/` 目录需要重写，后端与界面**完全复用**。

## 3. 架构

```
┌─ Electron 主进程 (main.js) ──────────────────────────┐
│  · 拉起子进程: .venv\python.exe server.py --port 8760 │
│  · 轮询 /api/stats 就绪 → 再开窗（窗口先出，内容后到）  │
│  · IPC: 定位 / 取件 / 建索引                          │
│  · 退出时终止子进程                                    │
└───────────────┬──────────────────────────────────────┘
                │ IPC（不再需要 HTTP 端口）
┌───────────────▼──────────────────────────────────────┐
│ 渲染进程（无 Node 权限，图片走自定义协议 thumb://）      │
│  · 检索 / 入库 / 增量 三个视图                         │
└───────────────────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────┐
│ **Node 后端（Electron 主进程 + worker 线程）**         │
│  · @huggingface/transformers + onnxruntime-node       │
│  · device: 'webgpu'（失败回落 cpu），dtype fp32        │
│  · 索引 index.bin（头部 JSON + float32 块）             │
│  · 能力: search / thumb / reveal / collect /          │
│          copy / index(status·start·cancel) / ingest   │
└───────────────────────────────────────────────────────┘
```

> **架构已因 spike 结果改写**：不再有 Python 后端、不再有 HTTP 端口、不再有子进程。
> 依据见 SPEC-app.md §3（WebGPU 0.42 s/张；文本与 torch bit-exact；DML/CUDA 均不可用）。

**关键设计决定**：渲染进程**不直接访问文件系统**，图片一律经 `thumb://<id>` 自定义协议。
- 好处：不必放宽 `webSecurity`；缩略图天然可缓存；单进程无端口冲突
- 代价：缩略图多一次 IPC/协议往返（本地，实测可忽略）

**安全基线**：`nodeIntegration: false`、`contextIsolation: true`，能力经 `preload.js` 白名单暴露。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 首次载模型 ~11 秒 | 用户以为卡死 | 窗口先出、显示"正在载入模型"；后端启动即后台预热（现状已支持） |
| **C: 仅剩 19.7 GB** | Electron 下载/构建挤爆系统盘 | npm 缓存改到 `D:\npm-cache`；构建产物在 D: |
| **G: 仅剩 44.3 GB** | 误写库盘 | 取件目标固定 `E:\素材待用\`；素材库只读（P5 用 mtime 核对） |
| 端口 8760 被占 | 后端起不来 | 启动时探测空闲端口，把实际端口传给渲染进程 |
| 沙箱/杀软拦截 Python 子进程 | 后端静默失败 | 用绝对路径、把 stderr 落 `data\app.log`、就绪探测超时则弹明确错误 |
| 索引与检索抢 GPU | 检索变慢/超时 | T1.3 互斥：建索引期间检索返回 409 + 提示 |
| 40 个扩展名与内容不符的图 | 缩略图 404 | 后端 `/api/thumb` 已有 PIL 回退（现状已处理），P3 验证要覆盖这几张 |
| Electron 首次安装需联网 | 无法安装 | 一次性：安装阶段联网，运行阶段离线 |
| 改 DSH 配置写坏 | DSH 起不来（**已发生两次**） | 只在 P6 动；先备份、用 `[IO.File]::WriteAllText` + `UTF8Encoding($false)`、写完字节校验、失败自动回滚 |
