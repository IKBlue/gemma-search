①目标

做一个独立桌面应用，管住本地素材库：找得到、看得见、取得到、收得进、管得住。 不再依附 DSH（此前做过右栏插件，已撤销并清除）。

为什么不能沿用现有形态

MCP 工具（现状） 只能在 DSH 会话里用；我给你路径，但你在 DSH 里打不开 G:\ 的图（实测 present.open 只认工作区文件，返回 500）

HTTP 界面已有缩略图网格，但要手动起服务，且不算"应用"
DSH 右栏插件侵入配置、槽位契约不确定、曾导致 DSH 起不来（已全部移除）

1双击启动 ≤ 5 秒出可用窗口
2文本查询（热）P50 ≤ 80 ms · P95 ≤ 150 ms；图像查询（热，webgpu）P50 ≤ 1.0 s · P95 ≤ 1.5 s

CPU 回退时不做延迟承诺，界面必须显示回退状态

9断网可用；全程对素材库的写入只经入库流程（预检+审计+可撤销）

④spike 实测结论

在写应用之前，用 20 张库内图 + 5 句中文做了跨运行时对照实验，回答一个问题： ONNX 的向量能不能与现有索引（torch 产出）可比？

1.000000
文本塔 vs torch（余弦）
5 条查询、两个 seq 档，全部 bit-exact → ONNX 导出忠实
0.9957
图像 vs torch（中位余弦）
差 0.4%，来自图像预处理（resize）而非模型 → 索引必须用同一运行时重建
0.42 s/张
WebGPU 编码（seq140）
CPU 1.32 s；torch/GPU 0.16 s
逐位一致
WebGPU vs CPU 向量
小数点后 6 位相同 → WebGPU 不引入额外漂移

⚠ 由此确立的一条铁律：预处理也绑定索引

跨 seq 混用**绝对不行**：torch(140) vs ONNX(280) 的最差余弦只有 0.7597。 所以索引里必须记录 model / precision / seq / dtype，任一不符拒绝检索并提示重建—— 否则不报错、只是结果悄悄变差，这是本项目最危险的失败模式。

✓ 索引重建试点已通过

用新写的 Node 构建器跑了 100 张：100/100 编码成功、0 失败、2.41 条/秒 → 全量 3594 张约 25 分钟，与实测投影吻合。 新格式 index.bin（MAGIC + headerJSON + float32 块）与 稳定 UID 主键已落地。

⑤架构

渲染进程（界面）
三个视图：检索 / 入库 / 增量（+ 库管理）。nodeIntegration:false、contextIsolation:true； 图片经自定义协议 thumb://<uid>，渲染进程不接触文件系统
▲ IPC（类型化、无端口、无 CORS、无鉴权、浏览器无法调用）
core/engine.mjs —— 传输无关的引擎（本期核心）
纯逻辑，无 Electron / 无 HTTP / 无全局状态。方法：search · item · thumbPath · reveal · collect · ingest · mutate · scan · indexStatus · indexStart/Cancel。 测试直接打它，所以不需要 HTTP 也能测
▼ worker 线程（编码不冻结界面）
推理层
transformers.js + onnxruntime-node，device:'webgpu'（回落 cpu），fp32，seq 140； 模型只加载一次，常驻主进程 worker
▼ 文件系统
数据层
索引 %APPDATA%\gemma-search\libraries\<lib_id>\{index.bin, items.json, meta.json}； 模型 model-cache\onnx\<repo>\<revision>\<precision>\； 库（只经入库流程写入）G:\model\<目录>\

为什么现在不加 REST

决定性理由：应用现在能移动/重命名/移出库。一旦挂到 http://127.0.0.1:<port>，你浏览的任意网页都能向 localhost 发请求—— 本机 HTTP 服务的 CSRF / DNS-rebinding 是已知攻击类，恶意页面可悄悄 POST /api/mutate 移走库里文件。 IPC 根本不存在这个攻击面。

localhost ≠ 安全：它挡的是"外部网络进来的人"，挡不住"从你浏览器里发起的请求"。

什么时候才值得加（触发条件）

想在手机/平板上浏览素材库
想让 DSH/MCP 复用同一个模型实例（否则再常驻一份 243 MB–1.6 GB）
想脚本化（定时扫描、从微信目录批量入库）
出现第二个客户端

届时只需新增 transports/http.mjs（约一天），并遵守安全基线： 只绑 127.0.0.1 · token 鉴权 · Origin 校验 · 写操作默认关闭 · 只按 lib_id+uid 寻址。

硬规则：绝不允许"半截状态"

「改 ID」「改目录」「移出库」必须图与包同时成功：先都写到目标名 → 校验字节一致 → 再删原件；任何一步失败即回滚。 绝不允许出现"图改了包没改"。

写入纪律（四步，缺一不可）

① 预检算出"将要发生的确切变更清单"：源→目标、重名、ID 冲突、体积
② 执行临时名写入 → 校验字节 → 原子替换/移动；多文件要么全成要么全回滚
③ 审计记 {时间, 库, uid, 操作, 前后路径, 结果}
④ 撤销任何一步都能反向执行；撤销本身也记审计

只读操作（检索/扫描/缩略图/浏览）永远不写库，且扫描前后比对库指纹，发现非本流程的改动就报警。

多库管理

操作行为
添加库选目录 → 扫描 → 有索引则按指纹校验复用，否则新建（0.42 s/张）
移除库只从注册表移除，绝不删文件（界面明确写这句）
重命名库只改显示名
重新指向（换盘）按指纹判断是否同一个库：一致则只改路径、不重建索引；不一致才要求重建
跨库移动素材图+包一起移；同 model/seq 时向量随迁，零重编码
扫描 / 重建索引按库进行，进度与取消独立

跨库检索的铁律

只有 model + precision + seq + dtype 全一致的库才能一起检索。不一致的库在界面标灰并写明原因 （如「seq280，与当前 140 不一致」），绝不静默混入。
