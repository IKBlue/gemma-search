0 · 三条基线原则

① 只建现在就要用的表

本轮 6 张；其余 14 张随功能上线（各加一条迁移）。所有者裁定 B。

② 每列都有出处

要么被某个操作用到，要么是扫描就能拿到的事实。口径 = field-map 的 55 个操作。

③ 接口只暴露表能支持的操作

为不存在的表开的接口一律不开 —— 先定表，再对接口。

两个数据库

userData/app.db（应用级 3 张）· <库根>/.gs.db（库级 3 张，跟着库走）

跨库外键不存在（SQLite 无此能力）⇒ asset.lib_id 只是普通 TEXT，不做 REFERENCES。这是两个库划分的必然代价，写进注释。

1 · 数据表（6 张）

库级 <库根>/.gs.db —— 3 张

asset

本轮 条目。一个条目 = 一张预览图 + 可选同名包。写入口只有一个：扫描。
字段类型约束说明
uidTEXTPK12 位小写 hex；扫描时匹配认领（先按 (lib_id, rel_path) 命中就保留原 uid）。
lib_idTEXTNOT NULL普通 TEXT（跨库外键建不出来，见 §0）。
folderTEXTNOT NULL分类目录 —— 浏览与筛选的主维度。
stemTEXTNOT NULL文件名主干（配对靠它；唯一来源在扫描器）。
display_nameTEXTNOT NULL界面显示名，可改 —— 不改磁盘。
rel_dirTEXTNOT NULL相对目录的规范形（库根 ⇒ 空串）；进 uid 公式。
rel_pathTEXTNOT NULL相对路径 —— 扫描匹配与唯一性的落点。
discovered_at_msINTEGERNOT NULL首次被发现时刻（「最近入库」要用）。

唯一约束 UNIQUE (lib_id, rel_path) —— 防止同一文件被登记两次（uid 不再由路径派生，路径唯一性必须显式声明）。
索引 (lib_id, folder) · (stem)。
本批刻意不加 deleted_at_ms（回收站）· dup_group_id（去重）· content_created_at_ms（按内容时间浏览）—— 都属后续功能。

asset_file

本轮 文件角色。缺包 = 少一行，不是一个 NULL 块。写入口同 asset：只有扫描。
字段类型约束说明
uidTEXTFK → asset.uidON DELETE CASCADE同库外键 —— 表在同一文件里，所以 CASCADE 成立。
roleTEXTCHECK preview / archive预览图 / 同名包。
rel_pathTEXTNOT NULL相对路径。
extTEXTNOT NULL扩展名。
size_bytesINTEGERNOT NULL大小（扫描事实）。
mtime_msINTEGERNOT NULL统一口径：BigInt mtimeNs / 1e6 截断，全库唯一写入口。
width · heightINTEGERNULL像素尺寸 —— 扫描就能拿到 ⇒ 现在就存，免得以后重扫。

主键 (uid, role) · 索引 (rel_path)。
本批不加 thumb_hash（首屏占位图，UI 增强）· content_hash_kind/value（去重功能，而且要真算哈希）。

asset_index_state

本轮 索引状态。存时刻，不存枚举 —— 「待重编码」是算出来的，不是存出来的。
字段类型约束说明
uidTEXTPKFK → asset.uidCASCADE1:1 于条目。
encoded_at_msINTEGERNULL成功编码时刻；NULL = 从未成功。
encoded_mtime_msINTEGERNULL编码时该文件的 mtime ⇒ 与当前 mtime 不等 = 待重编码。
compat_keyTEXTNULL编码时用的兼容键 ⇒ 与库的 compat_key 不等 = 待重编码（模型换了）。
attempt_countINTEGERNOT NULLDEFAULT 0尝试次数。
last_error · last_error_at_msTEXT · INTEGERNULL失败原因 —— 没有它，「编码失败」这一档无法解释。
excluded_at_msINTEGERNULL用户主动排除索引（意图，优先级最高）。
checked_at_msINTEGERNULL上次核对时刻 —— 界面要能说「这是上次已知状态，可能过期」。

偏索引 (encoded_at_ms) WHERE encoded_at_ms IS NULL · (excluded_at_ms) WHERE excluded_at_ms IS NOT NULL。
状态 8 档全部派生（一个字都不存）：已排除 > 编码失败 > 编码中 > 图片丢失 > 已移除 > 待重编码 > 待编码 > 已编码。
本批不物化 needs_reencode（跨表比较无法索引；等浏览页要筛再迁移加列 + 对账）。

应用级 userData/app.db —— 3 张

app_meta

本轮 版本与迁移账本。写入口只有迁移。
字段类型约束说明
idINTEGERPKCHECK id = 1单行守卫 —— 不变式由 CHECK 保证，不靠调用方自觉。
schema_versionINTEGERNOT NULLCHECK >= 0应用级迁移版本；只有这一处真相。
created_at_ms · updated_at_msINTEGERNOT NULL建立 / 上次迁移时刻。

library_registry

本轮 库注册表。不可再生 —— 扫文件系统扫不出「你把哪个目录当库」。写入口只有 library* 那组方法。
字段类型约束说明
lib_idTEXTPK1–32 字符库标识；写进 uid 派生公式 ⇒ 一旦分配不可改。
rootTEXTNOT NULLUNIQUE库根绝对路径。登记前必须规范化（大小写 / 短名 / 尾斜杠）—— 否则 Windows 上 G:\Model 与 g:\model 能登两次。
display_nameTEXTNOT NULL界面显示名 —— 名字是你的，路径是事实。
enabledINTEGERNOT NULLCHECK 0/1DEFAULT 1是否参与检索 / 入库；停用不动任何文件。
compat_keyTEXTNULL这个库的索引是用哪套兼容键建的（合并检索的门限）。
sort_orderINTEGERNOT NULLDEFAULT 0INDEX侧栏顺序。顺序是你的，不该由路径字母序决定；同值按 lib_id 兜底，保证稳定。
registered_at_ms · updated_at_msINTEGERNOT NULL登记 / 修改时刻。

collect_dir

本轮 取件白名单 —— 安全边界。写入口只有 collectDir* 那组方法。
字段类型约束说明
dir_idTEXTPKnanoid。
labelTEXTNOT NULLUNIQUE目录名（界面显示）。
abs_pathTEXTNOT NULL取件只允许写进这些目录，其余一律拒绝。
is_defaultINTEGERNOT NULLCHECK 0/1DEFAULT 0默认目标。
created_at_msINTEGERNOT NULL加入时刻。

只允许一个默认（偏唯一索引，机械保证，不靠界面自觉）：
CREATE UNIQUE INDEX uniq_collect_default ON collect_dir ((1)) WHERE is_default = 1

3 · 迁移与重建（绿地）

项定稿
迁移机制一套实现参数化出两套账本：应用级用 app_meta.schema_version、库级用 schema_version。
新旧关系不支持旧库升级：发现旧版 .gs.db ⇒ 丢弃重建，并如实告知用户。
重建规则丢事实层、留过程层与意图层 —— 本批：事实 = asset / asset_file（可重建）· 过程 = asset_index_state（尽量留）· 意图 = 无。
保留命名空间.gs-* ∪ .gs.db 家族 ∪ .gs-staging/（唯一实现 gs-names.ts）；app.db 在 userData，不属于库内保留名。

6 · 这份设计证明不了什么

  • 字段取舍是按 field-map 的操作引用数做的判断，不是实测（没跑过 100 条之外的数据量）。
  • 「6 张够用」的边界是 S1–S4 这条链路（扫描 → 索引 → 检索 → 详情 → 取件）。
  • 状态 8 档的派生规则写全了，但实不实际要等 S3 / S4 用真数据验。
