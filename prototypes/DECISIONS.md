## 一、这一版的结构（三轮改动后的最终形态）

```
顶栏：[范围胶囊] [搜索]
├─ 找（首页）  全部库的素材墙 · 瀑布流 · 跨库时卡片标来源
├─ 库（管理）  库卡片列表 → 点进去是该库的「条目操作页」（加/删条目、扫描、体检、回收站）
├─ 收          往某个库入库（目标库在动作发生时选）
├─ 交付        把素材复制给别人
└─ 工具        回收站 · 任务 · 体检 · 文档(门控) · 设置
```

**两个概念被刻意分开**（这是三轮里最重要的一条改动）：

| 概念 | 含义 | 默认值 |
|---|---|---|
| **范围 scope** | 你**看到**哪些库的素材，可以是"全部库" | 全部库 |
| **当前库 currentLib** | **写操作**落在哪个库（收 / 交付 / 体检） | 未选，动作发生时问你 |

把这两个混成一个变量，就会出现"在全部库范围下点收，东西收到哪去了"这种含糊。
新增"移动硬盘 · 2308 批次"就是为了让两种状态都能被看到：主库与它 `compat` 相同（能合并），
备份盘 `seq196` 不同（被排除且**说明原因**）。

## 二、和现有规格正面冲突、需要你确认的三条

### 1. 「删除条目」推翻了写入不变式（**最重要**）

- `SPEC.md` §2.1 原文：除保留命名空间外，**素材目录一律只读**（检索/浏览/缩略图/体检零写入）
- 你现在要的"删除条目"**必然**要动素材文件 ⇒ 这是**改需求**，不是改样式
- 你选的档位：**移进回收站、可恢复**（我认为这是唯一安全的选择）
- 我据此定的规则：
  - 删除 = 移到 `<库根>/.gs-trash/<事务id>/` + 记一条事务日志
  - 界面上**永不出现"删除"两个字单独出现**，只说"移入回收站"
  - 只有回收站里才有"彻底删除"，且它是一个红色确认框 + 默认焦点在取消
  - 因此 `.gs-trash/` 必须进**保留命名空间**（`packages/engine/src/gs-names.ts`），
    否则扫描器会把回收站里的东西当成素材 —— 这个坑本项目已经踩过两次

**需要你做的**：确认 §2.1 改成"素材目录只读（**回收站命名空间除外**）"，
并在 SPEC 里补一个 `trash` 相关的错误码（如 `TRASH_FAILED`、`TRASH_RESTORE_CONFLICT`）。

### 2. 模型路径优先级（第一轮就提过，仍未确认）

`SPEC.md` §2 原顺序把你**显式指定**的路径放在最后。所有者已授权按新顺序实现并等你复核：
**你指定的 → 程序目录 → 用户数据目录**。我按新顺序做的。

### 3. 首页从"库列表"改回"找"（本轮）

上一版我把库列表当首页 —— 那是错的，它让你每次找东西前先做一次管理动作。
现在首页是**全部库的素材墙**，库列表退成管理页。

## 三、我替你定的（你没被问到，但可以推翻）

| 决定 | 理由 | 若不同意会怎样 |
|---|---|---|
| **瀑布流用 CSS 多列** | 素材长宽比不同，等高网格要 `cover` 裁掉内容，而"看图挑东西"最不能接受看不到全图 | 换成 JS 布局可得到严格的行优先顺序，代价是复杂度和滚动性能 |
| 来源库角标**只在跨库时**显示 | 单库范围内每张都一样，标了是噪音 | 一直显示也合理，只是更吵 |
| 卡片动作**悬停才出现** | 沉浸型的代价是触屏/键盘摸不到；已用"键盘移动也显示"+"右键菜单"补 | 常驻显示会更"工具化" |
| 搜索框**清空 = 回到浏览** | 否则你要先按搜索才发现"其实我没在搜" | — |
| 兼容性不同的库**列出来但标注"不会被检索"** | 直接藏掉会让人以为这个库丢了 | — |

## 四、验证到什么程度（**请按这个口径理解可信度**）

| 手段 | 结果 |
|---|---|
| 结构自检（JS/CSS/标签/id/悬空引用/块内重复令牌） | ✅ 通过 · `data/_proto-check.mjs` |
| 对比度按令牌真值复算（深/浅/跟随系统三档） | ✅ 全部达标 · `data/_proto-contrast.mjs` |
| 语义契约检查（compat 规则 / 删除语义 / 范围分离） | ✅ 通过 · `data/_diag14.mjs` |
| **真浏览器 14 步点击验收** | ✅ 全部通过，`pageerror 0` · `data/_proto-verify2.mjs` |
| 命中区实测（真窗口量） | ✅ 0 个不达标 |

**真浏览器验收抓到的 3 个缺陷**（都已修复，值得记下来因为它们静态查不出）：

1. **`--thumb-ratio` 没生效**：我给 `.thumb` 写死了 `aspect-ratio: 4/3`，
   而数据里的比例是内联的 `--thumb-ratio` ⇒ 规则其实在按 4:3 渲染。
   自检过了，因为两边都是合法 CSS —— **只有真渲染才看得出来**。
2. **回收站里的按钮点不动**：删除后的斜纹遮罩 `.card.trashed .thumb::after` 绝对定位铺满图片，
   把"恢复/彻底删除"按钮一起挡住了。按钮可见、可聚焦，但**点不动**。
   修法：视觉遮罩一律 `pointer-events: none`。
3. **"全部库"其实只有一个库**：我的假数据让所有库的 `compat` 都不同，
   于是默认范围按规则只剩一个库 —— 角标全都不显示。
   **这不是渲染 bug，是我的假数据自相矛盾**。加了第三个同 compat 的库才把两种状态都做对。

**还没验证的**：真实文件操作、索引与事务接线、打包态、真机 E2E。
原型**不碰你硬盘上任何文件**——它只在内存里改假数据。
