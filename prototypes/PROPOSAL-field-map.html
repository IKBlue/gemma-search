字段地图 · 哪个字段用在哪一块

schema 文档是按表组织的——那是给写迁移的人看的。 这份按屏组织，回答你的问题：能操作什么 · 在哪操作 · 动了哪些字段 · 有什么用。

屏幕与操作钩子是从 prototypes/apple-style-redesign.html 实际提取的（12 屏），不是回忆。

先分清：字段其实只有四类，你只需要主动管第一类

你觉得"看不清哪个字段用在哪"，根因是 18 张表混在一起看。 但按谁写它分，只有四类——其中三类你根本不用管。

A

你填的

✅ 你直接编辑 · 丢了就没有了
  • asset_user_meta — 评分 · 备注 · 收藏
  • tag / asset_tag — 标签
  • collection / collection_item — 集合
  • asset_index_state.excluded_at_ms — 排除索引
  • collect_dir — 取件白名单目录
  • library_registry — 库名 · 顺序 · 启停
B

系统看出来的

🔒 只读 · 你改不了，也不该改
  • asset — 名称 · 目录 · 分类
  • asset_file — 路径 · 大小 · 修改时间 · 宽高
  • 改它们的唯一办法是改磁盘上的文件， 然后扫描一遍。
C

系统跑出来的

⚠️ 你只能"触发重跑"，不能直接改
  • asset_index_state — 索引状态（8 档）
  • job — 任务进度
  • health_run / health_finding — 体检结果
  • 想让它变，只有一条路：重新编码 / 重新体检。
D

系统记的流水

📋 只读 · 你做的事留下的痕迹
  • asset_export — 取件 / 交付历史
  • activity — 操作记录
  • recent_view / recent_query — 最近查看 / 搜索
所以"哪个字段用在哪一块"的答案是： B / C / D 三类你不操作，只看结果；真正需要你关心的是 A 类那 6 组， 它们分别出现在下面五个地方：条目详情页（评分/备注/标签/集合/排除）、 设置页（取件目录）、首页与库页（库名/顺序/启停）、 卡片与列表（收藏）、以及交付流程。

二、反过来查：这个字段出现在哪

你在 schema 文档里看到一个字段名、不知道它是干嘛的，就查这张表。

三、哪些字段你看不到，但决定了你看到什么

这几个字段从不出现在界面上，但少一个界面就是错的：
  • asset_index_state.checked_at_ms —— 界面上"这个状态是何时检查的"。 没有它，库里显示的可能是一个月前的状态而你不知道。
  • asset_file.content_hash_kind —— 单独看不出用处， 但没有它，换哈希算法后旧哈希无法解释。
  • job.job_id 与 health_run.job_id —— 让体检复用同一套任务机制。没有这条关联，取消/进度/续跑就得写第二份。
  • asset_export.asset_name —— 历史快照。 没有它，条目改名后历史记录里就只剩一个看不懂的 uid。
  • library_registry.sort_order —— 没有它，每次重启库的顺序都可能变。
这份地图里有两处是"提案新增、原型还没有"的，我在表里标成 v1.2 新：按索引状态筛选（库页新芯片）与 按文件名找（搜索页关键词那条路）。其余操作都是原型里已经有的钩子。 ⇒ 也就是说，这套 schema 能支撑的比你当前界面能做的多，那两处是明确的下一步。
